# 一键同步本地预设手帐与印刷规格

## 启动

在任意目录执行以下命令即可正式同步，无需先发布服务器代码：

```bash
bash /Users/dream/Documents/project/Reference/SparkService/scripts/sync_local_catalog.sh
```

正式执行会清除服务器公开预设目录并用本地数据替换；先备份，再暂停 API、worker、beat，在一个数据库事务中替换并逐行核对，最后恢复服务。操作期间 API 会短暂不可用。前端容器、MySQL、Redis 和宿主机 Nginx 保持运行。

第一次建议先只读预检：

```bash
bash /Users/dream/Documents/project/Reference/SparkService/scripts/sync_local_catalog.sh --dry-run
```

`--dry-run` 会导出本地快照，将脚本和快照上传至服务器的本次工作目录，并启动一次性容器核对模型、关联数据和全部 OSS 对象；不会清空数据库、停止应用或修改业务数据。`--check-target` 只检查本地 Git 与 SSH 配置，不连接服务器。

## 本地数据从哪里读取

- 工具目录：`/Users/dream/Documents/project/TravelDiary/PSD转换工具`。
- 配置：工具目录下权限为 600 的 `.env.publish`，通过 dotenv 解析，不使用 shell source。
- 数据库：这份配置指定的本机 `127.0.0.1:3306/sparkservice`，不使用 SparkService 的生产 `.env` 充当本地源配置。
- 读取已登记到本地数据库的管理后台数据，不从 output 文件夹猜测“最新”文件，也不重新转换 PSD 或重复发布版本。
- 工作站和服务器当前使用同一 OSS 桶 `zhaodkdream`，资源直接复用对象 key。脚本检查每个历史版本、草稿及素材修订所引用的全部对象存在，且已知长度匹配。不输出密钥或签名 URL，不删除 OSS 对象。
- 如有尚未通过工具发布到本地数据库的新 PSD，先完成原工具发布，再运行本脚本。

可以使用 `PRESET_TOOL_DIR`、`PRESET_LOCAL_ENV`、`PRESET_PYTHON` 指定工具目录、配置与后端 Python。服务器默认 `root@39.106.39.110:/root/2026`，共用 release_target_guard.sh，拒绝其他 IP 或 SSH HostName 重定向，要求 TravelDiary 分支。已有部署或同步持锁时直接失败，不取消它。

## 同步范围

| 数据 | 行为 |
| --- | --- |
| Series | 系列名称、排序、启用状态按本地同步，包括停用的“专属定制”目录；仍被服务器私人定制引用的额外系列保留 |
| Template | 所有公开手帐，包括草稿、已下架、空白手帐；保留 UUID、标题、排序、修订和 current |
| Version | 所有历史发布版本、全部单页、图层、文件清单与 OSS 依赖快照；current 恢复为本地实际版本 |
| SearchTaxon / CatalogEntry / CatalogEntryTerm | 分类词、搜索索引、单页和阅读单元索引及关联；搜索 revision 递增使旧游标失效 |
| MaterialLibrary / LibraryVersion / LibraryItem | 贴纸库、背景库、全部库版本和排序、手帐版本关联 |
| Material / MaterialRevision / ResourceBlob | 稳定素材身份、全部关联历史修订、分类关键词、资源和缩略图元数据；私人定制正在引用的共享记录保留 |
| 预设 Event | 同步内容发布历史，actor 置空，不把本机用户数字 ID 错映射为服务器用户 |
| print_orders.Product | 所有本地印刷规格，包括 A5/B5 材料、尺寸、工艺、数量限制、费用、配送地区、制作周期、售后、打样记录/时间/确认人、开放状态 |

印刷规格按 UUID 或相同尺寸匹配服务器商品，保留服务器已有 UUID 和订单外键；业务字段以本地为准，技术 revision 保持递增。匹配出多个规格时停止，不猜测。服务器多出的规格无订单则删除，有订单则下架保留。开放的本地规格必须具有完整材料、打样、配送、售后、数量和价格配置；脚本不会为未打样规格伪造通过记录或擅自开启受理。

本次开发时本地快照为：7 个系列、9 本公开手帐、19 个手帐版本、14 个素材库、19 个素材库版本、499 个素材、588 个素材修订、1,035 条素材资源元数据、4,713 个去重 OSS 依赖、2 个印刷规格。每次执行重新读取，不写死这些数量。

## 保留哪些数据

私人定制手帐及交付链、用户账号、订单、支付、物流、生产快照、反馈等均保留。不会导入本机私人定制、本机收藏、下载计划、用户或上传任务。服务器旧公开预设的上传记录、资源任务和下载计划会随目录清理；有未完成公开上传任务时在清除前停止。同 UUID 素材库的服务器收藏恢复保留，稳定素材 UUID 的收藏沿用；被本地删除的库/素材收藏随之移除。

整型数据库主键（版本、修订、库条目等）自动重新分配，所有关联统一映射，避免撞上服务器私人数据。UUID、素材身份、版本号、页面 ID 和对象 key 保留。底层全库、用户表、订单表不会清空；共享 OSS 对象不清理。

## 流程与失败处理

1. 校验分支、提交和最终 SSH 目标；本地一致性事务导出公开目录及印刷配置，检查关联完整及非空。
2. 上传本次快照和独立导入器；获得与发版共用的 `/root/2026/.deploy.lock`。
3. 校验模型结构、事务表、公开/私人 UUID 冲突、未完成上传任务、OSS 桶/端点/前缀；逐个 HEAD 检查所有资源。
4. 正式执行时使用服务器本机 `mariadb-dump --single-transaction --routines --triggers sparkservice` 保存压缩全库备份并检查 gzip 完整性；需要宿主机可通过本地 socket 执行该备份命令，否则在停止应用前退出。
5. 停止 API、worker、beat；核对数据包摘要仍与资源预检一致；使用 Django 原生关联删除顺序在 InnoDB 事务中替换公开内容，同事务同步印刷规格。
6. 逐行核对业务字段及映射后的所有外键，检查数据库约束；全部通过才提交。失败自动回滚数据库事务并尝试恢复应用。
7. 恢复原有服务；检查内部 API、实际 HTTPS API 与后台入口、四个服务运行状态及 Celery worker ping；保存导出、预检、导入报告和完整日志。

本机记录在源码 `tmp/preset-sync/<时间_随机串>/`，已被 Git 与发版包排除。远端数据库备份和报告位于 `/root/2026/shared/backups/preset-sync/<同名目录>/`，目录/文件仅当前用户可读。

导入事务失败不会保留半套目录。若事务已经成功提交但恢复服务或健康检查失败，目录已经更新；脚本明确报错并保留报告，不盲目自动重跑或恢复全库，以免覆盖其他业务数据。需核对远端 import-report.json、服务日志和当前状态后处理。数据库备份恢复必须单独审查，不能把全库备份直接用于无人值守回滚。
