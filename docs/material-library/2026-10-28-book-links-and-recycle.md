# 整本手帐配套关联、回收站与 OSS 临时文件清理

日期：2026-10-28。状态：已在本地实现、迁移与验证；未发布生产。

## 后台操作

- 内容资源 → 贴纸管理 / 背景管理 → 素材包“更多” → 关联整本手帐：查看已有关系，按名称搜索手帐，选择固定包版本，确认新增或替换关联。
- 模板管理 → 选择整本手帐 → 贴纸与背景库：查看、关联、更换、取消同一组配套关系。每本手帐每种素材类型一个主包，一个包可以关联多本手帐。
- 所有关联配置在下一次发布整本手帐时形成固定版本快照。取消配置不删除已发布绑定，不更改用户作品、收藏或实际图片；素材包发新版也不会自动升级已经选定的包版本。
- 素材包“更多” → 删除整套：先展示版本、素材、手帐关联、历史引用和受保护文件占用，再输入完整名称并确认。存在下一版本配套关联或未结束同步任务时禁止删除。
- 回收站与 OSS 清理 → 回收站：显示软删除的包，支持恢复。恢复后维持下架，不自动重建配套关系。
- 回收站与 OSS 清理 → OSS 清理：扫描超过 7 天且上传授权过期的上传会话，确认后清理 staging 原图及缩略图。每次请求最多处理 10 个会话，任务持久化，允许中断后继续和失败重试。每次扫描最多 200 个会话；完成后可重新扫描后续会话。

## 当前明确保留的边界

**删除整套目前是可恢复的业务删除，不是永久删除。正式 OSS 原图、缩略图、封面和展示图不做物理回收。**

本地与生产共享同一 OSS，现有系统没有覆盖所有环境、模板快照、草稿、历史版本和同步任务的统一资源引用注册表。单个数据库的“无引用”不能证明文件可删，因此当前对所有正式资源保留保护；删除影响预览返回 protected_bytes、reclaimable_bytes=0 及原因。未增加不完整的“强制删除”旁路，也未设置 30 天自动永久清除。永久回收需后续补齐全环境引用注册、引用建立/删除的互斥协议及历史版本退役流程。

清理只对服务器登记的 material-uploads 临时目录发 OSS DELETE，不接受浏览器传入任意 object_key，不下载或中转文件字节。正式目录 blobs/ 永不进入当前清理任务。删除整套也不删除共享素材实体或其 revision。

## 数据与兼容

- 迁移 0010：MaterialLibrary.deleted_at / deletion_reason；TemplateMaterialLink；MaterialCleanupJob。将现有 template 外键关系回填到独立配置表并固定当前包版本，保留既有 TemplateLibraryBinding。
- 迁移 0011：MaterialUpload.staging_cleaned_at，已清理的会话不重复扫描；verified 上传保留 verified 状态，已确认的正式文件继续可用。
- 新建包不再设置单一 template 归属，选择手帐时只写独立关联表。旧 template 外键保留作为来源兼容字段，其唯一约束不会妨碍新关联或取消后另选新包。
- 整本发布由 bind_published_template 读取配置并创建不可变绑定；关联编辑使用模板行锁和 expected_revision，包删除使用包行锁、state_revision 及十分钟签名预览。清理使用任务及上传会话行锁，并在实际 DELETE 前重查过期条件。
- 客户端 schema=1 / schema=2 按整本手帐和发布版本解析配套包，包括无 template 外键的独立包。schema=2 的 template_version 必须同时传 template，避免只凭相同版本号误配其他手帐。
- 包删除后不能通过草稿、发布、上下架、预览签名和同步发布入口重新启用；必须先恢复。原手帐停用不再隐式停用可复用的公共贴纸包，包自身上下架独立控制。
- 列表当前成员数量、封面及同步摘要按页批量读取，避免逐包重复查询。

## 新增接口

均位于 `/api/v1/materials/manage/`，只收发 JSON：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET / POST | templates/{template}/links/ | 查看、设置或取消下一发布版本的配套配置 |
| GET / POST | libraries/{id}/links/ | 包角度查看关联、列出可选版本及设置配置 |
| GET | libraries/{id}/deletion-preview/ | 删除影响与限时预览 token |
| POST | libraries/{id}/recycle/ | operation=delete / restore，检查 state_revision；删除还需 token、confirm_title |
| GET | libraries/?recycle=1&paged=1 | 分页回收站 |
| GET / POST | cleanup/ | 最近 20 个任务 / 创建扫描预览 |
| POST | cleanup/{job}/execute/ | 执行或继续一个批次，返回逐会话结果 |

关联修改沿用管理员手帐编辑权限兼容，并检查素材编辑权限；独立删除 / 恢复 / 清理要求 `material_library.delete_materiallibrary` 或超级管理员。options 返回 can_link / can_delete，前端据此显示操作。清理错误不保存或回传带签名 URL、密钥的 OSS 异常原文。

命令行 `python manage.py cleanup_material_uploads` 默认 dry-run，不修改数据库或 OSS；`--execute` 才创建持久任务并执行，`--days` 下限为 7 天。该命令复用后台同一清理逻辑，不配置新的自动定时删除。
