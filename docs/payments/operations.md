# 印制支付与退款运营

## 状态与处理

支付记录保留原支付事实；取消订单不会把成功支付改成失败。支付列表同时展示订单和关联退款，退款全额成功后才把订单标记为已退款。

退款：pending（等待提交）→ processing（渠道处理中）/ unknown（结果待核实）/ blocked（明确受阻）/ exception（人工处理）→ success。

- query：只查询，不提交退款。渠道未找到退款时保留已知受阻原因。
- retry：管理员核对订单、金额、原因并二次确认后，先查已提交记录，再用同一退款号重试。
- pause：暂停自动处理；仍可查询。
- resume：二次确认后恢复自动处理并立即核对，重用原退款号。
- auto：对账任务按照 next_check_at 执行。余额不足间隔六小时，不受十次技术失败上限影响；权限/配置/其他明确业务拒绝暂停。连续十次结果不明则暂停等待人工核对。

所有网关调用在数据库事务外执行，退款处理使用租约防并发，重试不新建退款号。

## 成功依据

支付宝退款返回 fund_change=Y 且订单、交易号与金额匹配时确认成功；fund_change=N 或缺失时查询原退款单，以 REFUND_SUCCESS 与匹配金额确认。code=10000 不单独作为退款成功依据。查询空退款信息不视为退款成功。

对已成功退款不重新提交。客户端返回与支付 SDK 回跳不作为资金成功凭据。

## 权限

- print_orders.view_paymentattempt：查看账务、概览、审计及导出。
- print_orders.query_payment：查询渠道结果与关闭未支付交易。
- print_orders.refund_order：重试退款、暂停/恢复自动处理。
- print_orders.change_paymentchannel：维护密钥、渠道配置、发布。
- print_orders.change_order：进入印制订单处理。

更强的查询/退款权限包含读取所需账务记录；配置权限不自动授予账务处理权限。页面使用服务端 access 返回的能力隐藏不可用入口，服务端仍独立鉴权。

## 页面

默认进入支付交易待办；渠道配置独立标签。列表可按订单/支付/退款/渠道流水号、作品、渠道、状态、北京时间日期范围、退款原因分类搜索。支持操作历史服务器分页、操作者/结果/关联记录搜索、订单与支付退款互跳。

详情以北京时间和元展示，保留渠道错误码、操作人、状态变化和执行结果。失败后重载最新记录；自动刷新不覆盖当前筛选。

账务汇总及 CSV 只来自内部支付退款记录。订单快照金额、已收、已退、待退不代表渠道结算余额。手续费、冻结资金和实际结算请核对支付宝/微信账单；当前不推算或伪造这些金额。首期仅全额退款。

## 联调

签名到期且未查到交易记录：close_kind=expired_absent，仅验证签名到期场景。
渠道返回关闭或关闭接口后查询确认：close_kind=gateway，可计入取消关单验证。
未下发支付参数而作废不计入关单验证。已付款测试突出退款状态，不再展示扫码到期警告。启用渠道仍允许跳过联调，必须格式检查与二次确认。
