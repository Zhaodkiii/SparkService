# 一、背景与目标

## 1.1 业务背景

SparkService 已具备后台管理系统基础能力，包括管理员登录、RBAC 权限、用户管理、AI 配置、通知管理、任务管理、医疗数据查看与操作审计。随着产品运营内容增加，需要在后台建立统一的文档系统，用于沉淀和发布结构化内容。

当前可能存在的问题：

1. 运营内容依赖代码发布或临时配置，更新成本高。
2. 健康科普、帮助中心、FAQ、公告等内容没有统一管理入口。
3. 缺少草稿、预览、发布、定时发布、下架和历史版本能力。
4. 内容缺少分类、标签、搜索、多语言、分享链接、引用来源和合规字段。
5. 缺少内容操作审计，不方便追踪“谁在何时修改了什么”。

## 1.2 建设目标

文档系统一期目标：

1. 支持后台创建、编辑、预览、直接发布、下架、归档和软删除文档。
2. 支持分类、标签、封面、摘要、Markdown 正文、分享链接、SEO 预留、来源引用等内容元数据。
3. 支持草稿、已发布、已下架、已归档等状态流转；一期不做强制审核流。
4. 支持文档版本快照，保证发布后内容可追踪、可回滚。
5. 支持中文、英文等多语言内容管理。
6. 支持按标题、分类、标签、状态、语言、作者、发布时间检索。
7. 接入现有后台 RBAC 权限体系和 `AdminAuditLog` 审计体系。
8. 为 App 内容流、App 内详情页和分享落地链接预留公开内容接口设计。
9. 统计文档点击量和阅读时长，不做点赞、收藏、分享数统计。

## 1.3 非目标范围

一期不包含：

1. 不做复杂协同编辑，例如多人实时在线编辑。
2. 不做完整 CMS 页面搭建器，例如拖拽式页面装修。
3. 不做评论系统，评论可以作为后续独立模块。
4. 不做内容付费、会员专栏、广告投放。
5. 不做全文搜索引擎接入，优先使用数据库基础搜索；后续可接 Elasticsearch / Meilisearch / OpenSearch。
6. 不做点赞、收藏、评论和分享数统计。
7. 不实现“发布新文章后自动推送通知”，仅预留与现有通知系统联动的扩展点。
8. 不区分“帮助中心文档”和“文章资讯”等多个内容类型，一期统一为一类内容。

# 三、核心业务流程

## 3.1 文档生命周期

```text
草稿 draft
  -> 已发布 published
  -> 已下架 offline
  -> 已归档 archived

任意非删除状态
  -> 软删除 deleted
```

## 3.2 发布流程

1. 编辑创建文档草稿。
2. 编辑填写标题、摘要、分类、标签、封面、Markdown 正文、语言、引用来源。
3. 编辑点击预览，确认移动端和后台展示效果。
4. 管理员点击发布，可立即发布或设置 `published_at` 定时发布。
5. 发布前系统校验医疗健康内容是否已填写参考来源。
6. 发布后生成发布版本快照。
7. 后续修改已发布文档时，默认新建草稿版本，不直接覆盖线上内容。

## 3.3 下架与回滚流程

1. 管理员对已发布文档执行下架。
2. 系统记录下架原因、操作人、操作时间。
3. 如需恢复，管理员可从历史版本选择一个版本重新发布。
4. 每次重新发布都生成新的版本快照。

# 四、功能需求

## 4.1 文档列表

### 页面入口

后台管理系统菜单：

```text
Spark Admin
  - 仪表盘
  - 异步任务
  - 用户管理
  - 通知中心
  - 版本控制
  - AI 场景配置
  - 权限管理
  - 审计日志
  - 对话
  - 医疗数据
  - 文章模块
    - 文章总览
    - 文章管理
    - 文章编辑
    - 分类管理
    - 标签管理
    - 多语言管理
    - 版本记录
    - 阅读数据
    - 来源合规
    - 回收站
```

### 列表字段

| 字段 | 说明 |
| --- | --- |
| 标题 | 文档标题，点击进入编辑/详情 |
| 分类 | 所属分类 |
| 标签 | 最多展示 3 个，超出折叠 |
| 状态 | 草稿、已发布、已下架、已归档 |
| 可见性 | 公开、私密、未列出 |
| 语言 | 中文、英文等语言标识 |
| 作者 | 创建人/最近编辑人 |
| 点击量 | App 端详情点击统计 |
| 平均阅读时长 | 用户阅读时长统计 |
| 发布时间 | 已发布内容展示发布时间 |
| 更新时间 | 最近一次编辑时间 |
| 操作 | 预览、编辑、发布、下架、复制链接、删除 |

### 筛选条件

| 条件 | 说明 |
| --- | --- |
| 关键词 | 标题、摘要、slug 模糊搜索 |
| 分类 | 支持一级/多级分类筛选 |
| 标签 | 支持多标签筛选 |
| 状态 | 按文档状态筛选 |
| 可见性 | 公开、私密、未列出 |
| 语言 | 中文、英文等语言筛选 |
| 作者 | 按创建人或最近编辑人筛选 |
| 发布时间 | 起止时间 |
| 是否置顶 | 筛选置顶内容 |
| 是否推荐 | 筛选推荐内容 |

## 4.2 文档编辑

### 基础字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 标题 | 是 | 最多 255 字符 |
| URL 别名 `slug` | 是 | 同语言下唯一，用于 App 分享链接和 Web 预览页 |
| 语言 `locale` | 是 | 默认 `zh-CN`，支持后续英文等多语言 |
| 摘要 | 否 | 最多 500 字符，用于列表页和分享 |
| 封面图 | 否 | 存 OSS/CDN URL，不存 Base64 |
| 正文 | 是 | Markdown |
| 正文格式 | 是 | 固定为 `markdown` |
| 分类 | 否 | 一篇文档默认一个主分类 |
| 标签 | 否 | 支持多标签 |
| 可见性 | 是 | 公开、私密、未列出 |
| SEO 标题 | 否 | 分享落地页和后续 Web SEO 预留 |
| SEO 描述 | 否 | 分享落地页和后续 Web SEO 预留 |
| 来源链接 | 否 | 外部来源或原文地址 |
| 参考文献 | 是 | 医疗健康内容必须填写，JSON 结构化存储 DOI、期刊、指南、政策来源 |

### 编辑器要求

1. 一期固定使用 Markdown 编辑器。
2. 支持图片上传到对象存储，正文中只插入 CDN URL。
3. 支持自动保存草稿，建议每 30 秒保存一次。
4. 支持离开页面前提示未保存内容。
5. 支持预览用户端效果。
6. 支持字数统计、阅读时间估算。
7. 支持插入表格、引用、代码块、图片、分割线。
8. 医疗/健康类内容必须支持“参考来源”结构化录入，未填写时禁止发布。

## 4.3 分类管理

分类用于建立内容目录结构，适合低频变动、强层级的内容组织方式。

### 功能要求

1. 支持新增、编辑、启用、停用分类。
2. 支持多级分类，使用 `parent_id` 建立树形结构。
3. 支持拖拽或输入 `sort_order` 排序。
4. 分类停用后，不影响历史文档展示，但新文档不可选择。
5. 删除分类前需检查是否存在关联文档。

## 4.4 标签管理

标签用于灵活聚合内容，适合高频变化、弱层级的运营主题。

### 功能要求

1. 支持新增、编辑、合并、停用标签。
2. 标签名称和 `slug` 全局唯一。
3. 支持展示标签关联文档数量。
4. 支持通过标签反查文档。
5. 删除标签前需解除或迁移关联关系。

## 4.5 发布管理与合规校验

一期不做严格审核流，允许具备发布权限的管理员直接发布。系统需要在发布前做必要的规则校验，避免缺字段、缺来源或多语言关系错误导致线上内容不可用。

### 发布动作

| 动作 | 说明 |
| --- | --- |
| 保存草稿 | 保存但不对用户端公开 |
| 发布 | 管理员直接发布，支持立即发布或定时发布 |
| 强制下架 | 对违规或过期内容下架 |
| 归档 | 对不再维护但需要留存的内容归档 |

### 发布前校验

每次发布需要校验：

1. 标题、slug、语言、正文、可见性不能为空。
2. 同语言下 `slug` 不能重复。
3. 医疗健康内容必须填写 `source_url` 或 `references_json`。
4. Markdown 图片地址必须是可信对象存储或 CDN URL。
5. 如绑定多语言内容，同一翻译组内每种语言只能有一篇当前有效文档。

### 操作记录

每次发布、下架、归档和回滚需要记录：

1. 操作人。
2. 操作动作。
3. 操作原因。
4. 操作前状态和操作后状态。
5. 操作时间。

## 4.6 版本管理

版本管理是生产内容系统的关键能力，避免线上内容被误改后无法追溯。

### 功能要求

1. 每次发布生成一条不可变版本快照。
2. 每次从已发布内容继续编辑时，创建新的草稿版本。
3. 支持查看版本列表。
4. 支持查看版本详情。
5. 支持对比当前草稿与已发布版本的差异。
6. 支持选择历史版本回滚并重新发布。

## 4.7 用户端公开内容接口

虽然本文重点是后台管理系统，但数据结构应预留 App 端读取和分享链接能力。用户端默认指 App 内展示；Web 页面仅作为分享落地链接和后续 SEO 预留。

### 用户端能力

1. 获取已发布文档列表。
2. 根据 `slug` 获取文档详情。
3. 根据分类获取文档列表。
4. 根据标签获取文档列表。
5. 获取推荐/置顶文档。
6. 记录点击量。
7. 上报阅读时长。
8. 获取分享链接。

### 用户端限制

1. 用户端只能读取 `status=published` 且 `visibility=public` 的内容。
2. `visibility=unlisted` 内容只能通过直接链接访问，不出现在列表。
3. `visibility=private` 内容只允许后台或特定权限用户访问。
4. App 分享链接打开后优先唤起 App；未安装 App 时可展示轻量 Web 落地页。

# 五、数据模型设计

## 5.1 文档主表 `content_articles`

存储文档核心信息与发布状态。正文 `content` 体积较大，列表查询时不要 `SELECT *`，应只取列表所需字段。

| 字段名 | 数据类型 | 约束 | 索引 | 字段说明 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | PRIMARY KEY, AUTO_INCREMENT | 主键索引 | 文档主键 ID |
| `title` | `VARCHAR(255)` | NOT NULL | 普通索引/全文索引可选 | 文档标题 |
| `slug` | `VARCHAR(255)` | NOT NULL | 联合唯一 | URL 别名，用于 App 分享链接和 Web 落地页 |
| `locale` | `VARCHAR(16)` | NOT NULL, DEFAULT `zh-CN` | 联合唯一/普通索引 | 内容语言，例如 zh-CN、en-US |
| `translation_group_id` | `BIGINT UNSIGNED` | NULL | 普通索引 | 多语言翻译组 ID，同一内容的不同语言版本归为一组 |
| `summary` | `VARCHAR(500)` | NULL | 无 | 文档摘要，用于列表页和分享 |
| `cover_image` | `VARCHAR(500)` | NULL | 无 | 封面图片 URL |
| `content` | `LONGTEXT` | NOT NULL | 无 | 文档正文，固定存 Markdown 字符串 |
| `content_format` | `VARCHAR(30)` | NOT NULL, DEFAULT `markdown` | 普通索引 | 正文格式，一期固定为 markdown |
| `author_id` | `BIGINT UNSIGNED` | NOT NULL | 普通索引 | 创建人 ID，关联用户表 |
| `last_editor_id` | `BIGINT UNSIGNED` | NULL | 普通索引 | 最近编辑人 ID |
| `category_id` | `INT UNSIGNED` | NULL | 普通索引 | 主分类 ID |
| `status` | `TINYINT` | NOT NULL, DEFAULT 0 | 普通索引 | 状态：0草稿、2已发布、3已下架、4已归档 |
| `visibility` | `TINYINT` | NOT NULL, DEFAULT 1 | 普通索引 | 可见性：0私密、1公开、2未列出 |
| `is_top` | `BOOLEAN` | NOT NULL, DEFAULT false | 普通索引 | 是否置顶 |
| `is_recommended` | `BOOLEAN` | NOT NULL, DEFAULT false | 普通索引 | 是否推荐 |
| `sort_order` | `INT` | NOT NULL, DEFAULT 0 | 普通索引 | 排序权重，数值越小越靠前 |
| `view_count` | `INT UNSIGNED` | NOT NULL, DEFAULT 0 | 无 | 点击量/详情打开次数 |
| `read_count` | `INT UNSIGNED` | NOT NULL, DEFAULT 0 | 无 | 有效阅读次数，用于计算平均阅读时长 |
| `reading_time_seconds` | `BIGINT UNSIGNED` | NOT NULL, DEFAULT 0 | 无 | 累计阅读时长，单位秒 |
| `seo_title` | `VARCHAR(255)` | NULL | 无 | SEO 标题 |
| `seo_description` | `VARCHAR(500)` | NULL | 无 | SEO 描述 |
| `source_url` | `TEXT` | NULL | 无 | 来源链接或原文地址 |
| `references_json` | `JSON` | NULL | 无 | 参考文献、DOI、指南、政策来源等结构化引用 |
| `published_at` | `DATETIME` | NULL | 普通索引 | 实际发布时间，支持定时发布 |
| `offline_at` | `DATETIME` | NULL | 普通索引 | 下架时间 |
| `created_at` | `DATETIME` | NOT NULL | 普通索引 | 创建时间 |
| `updated_at` | `DATETIME` | NOT NULL | 普通索引 | 更新时间 |
| `deleted_at` | `DATETIME` | NULL | 普通索引 | 软删除时间 |

### 推荐索引

| 索引名 | 字段 | 用途 |
| --- | --- | --- |
| `uk_content_articles_locale_slug` | `locale,slug` | 根据语言和 slug 获取详情 |
| `idx_content_articles_translation_group` | `translation_group_id` | 获取同一内容的多语言版本 |
| `idx_content_articles_cat_status_pub` | `category_id,locale,status,published_at` | 分类下已发布文档列表 |
| `idx_content_articles_status_pub` | `locale,status,published_at` | 全站已发布文档列表 |
| `idx_content_articles_author_status` | `author_id,status,updated_at` | 作者维度后台筛选 |
| `idx_content_articles_top_pub` | `is_top,status,published_at` | 置顶内容查询 |
| `idx_content_articles_recommend_pub` | `is_recommended,status,published_at` | 推荐内容查询 |
| `idx_content_articles_deleted` | `deleted_at` | 软删除过滤 |

## 5.2 分类表 `content_categories`

分类通常与文档是一对多关系。通过 `parent_id` 支持多级分类。

| 字段名 | 数据类型 | 约束 | 索引 | 字段说明 |
| --- | --- | --- | --- | --- |
| `id` | `INT UNSIGNED` | PRIMARY KEY, AUTO_INCREMENT | 主键索引 | 分类 ID |
| `name` | `VARCHAR(50)` | NOT NULL | 唯一索引 | 分类名称 |
| `slug` | `VARCHAR(50)` | NOT NULL | 唯一索引 | 分类别名 |
| `parent_id` | `INT UNSIGNED` | NOT NULL, DEFAULT 0 | 普通索引 | 父级分类 ID，0 表示顶级分类 |
| `description` | `VARCHAR(255)` | NULL | 无 | 分类说明 |
| `sort_order` | `INT` | NOT NULL, DEFAULT 0 | 普通索引 | 排序权重 |
| `is_active` | `BOOLEAN` | NOT NULL, DEFAULT true | 普通索引 | 是否启用 |
| `created_at` | `DATETIME` | NOT NULL | 无 | 创建时间 |

# 九、性能与工程实现建议

## 9.1 列表查询优化

后台列表和用户端列表不要返回 `content` 正文字段，只返回标题、摘要、封面、分类、标签、状态、发布时间等轻量字段。

常见查询：

```sql
-- 用户端：获取某分类下已发布文档，按发布时间倒序
SELECT
  id,
  title,
  slug,
  summary,
  cover_image,
  published_at
FROM content_articles
WHERE category_id = 1
  AND locale = 'zh-CN'
  AND status = 2
  AND visibility = 1
  AND deleted_at IS NULL
ORDER BY published_at DESC
LIMIT 20;
```

建议命中索引：

```text
idx_content_articles_cat_status_pub(category_id, locale, status, published_at)
```

## 9.2 正文与富媒体

1. 正文一期固定存 Markdown 字符串。
2. 图片、视频、附件必须上传到对象存储，不允许 Base64 直接写入正文。
3. 后台上传接口需要限制文件类型、大小和 MIME。
4. 用户端渲染 Markdown 生成 HTML 时必须做 XSS 清洗。

## 9.3 搜索策略

一期：

1. MySQL/PostgreSQL 标题和摘要模糊搜索。
2. 分类、标签、状态、时间范围走结构化索引。

二期：

1. 接入全文搜索引擎。
2. 支持正文全文检索。
3. 支持关键词高亮、同义词、热词统计。

## 9.4 定时发布

如支持定时发布，建议：

1. 文档状态保持为草稿，`published_at` 到达后切换为已发布。
2. 使用 Celery Beat 定时扫描 `published_at <= now()` 的文档。
3. 发布动作需要生成版本快照。
4. 发布失败需要记录任务日志并可重试。

## 9.5 缓存策略

用户端高频读取内容可增加缓存：

1. 文档详情按 `locale + slug` 缓存。
2. 分类树缓存。
3. 热门/推荐文档列表缓存。
4. 发布、下架、删除后主动失效缓存。

# 十、安全与合规要求

## 10.1 XSS 与内容安全

1. 后台保存 Markdown 原文，用户端渲染为 HTML 前必须清洗。
2. 允许的 HTML 标签和属性需要白名单控制。
3. 图片链接建议限制为可信 CDN 域名。
4. 外链需要增加风险提示或 `rel="nofollow noopener noreferrer"`。

## 10.2 医疗健康内容合规

如果文档用于健康科普、报告解读、用药说明等严谨内容，必须增加以下规则：

1. 必填至少一个权威来源或参考文献。
2. 可选标记医学复查人，一期不做强制发布审核流程。
3. 页面展示“内容仅供参考，不能替代医生诊疗建议”。
4. 记录内容最后医学复查时间。
5. 过期内容提醒复审，例如超过 180 天未更新提示运营复查。

## 10.3 敏感信息防护

1. 文档正文不得包含用户个人隐私、真实手机号、身份证号、医疗记录原文。
2. 后台审计日志不得完整记录正文。
3. 删除和下架操作必须记录原因。
4. 批量操作需要二次确认。

# 十二、验收标准

## 12.1 功能验收

1. 管理员可以创建、编辑、保存草稿、预览、直接发布、下架和归档文档。
2. 分类和标签可以独立维护，并能正确关联到文档。
3. 文档列表支持关键词、分类、标签、状态、语言、发布时间筛选。
4. 已发布文档能通过 App 端公开接口读取。
5. 未发布、已下架、已删除文档不能被用户端公开读取。
6. 已发布文档再次编辑不会直接影响线上版本。
7. 发布时会生成版本快照。
8. 可以查看版本列表并回滚指定版本。
9. 关键操作会写入后台审计日志。
10. 没有权限的管理员无法访问或操作对应接口。
11. 医疗健康内容未填写来源或参考文献时禁止发布。
12. 支持同一内容维护中文、英文等多语言版本。
13. 用户可以在 App 内点击分享并获得可打开链接。
14. 系统可以统计点击量和阅读时长，不提供点赞、收藏、分享数统计。

## 12.2 性能验收

1. 后台文档列表默认分页，单页最大不超过 100 条。
2. 用户端文档列表不返回正文大字段。
3. 分类列表、标签列表、文档列表常用查询命中索引。
4. 10 万篇文档量级下，按分类、语言和状态分页查询应保持稳定。

## 12.3 安全验收

1. Markdown 渲染 HTML 输出前完成 XSS 清洗。
2. 图片和附件上传限制类型和大小。
3. 审计日志不保存完整正文。
4. 删除、下架、回滚等高风险操作需要记录原因。
5. 医疗健康内容必须记录来源或参考文献。

### 发布伪代码

```python
@transaction.atomic
def publish_article(user, article, published_at=None, comment=""):
    validate_publishable(article)
    old_status = article.status
    article.status = ContentArticle.Status.PUBLISHED
    article.published_at = published_at or timezone.now()
    article.last_editor = user
    article.save(update_fields=["status", "published_at", "last_editor", "updated_at"])
    version = ContentArticleVersion.from_article(article, created_by=user, change_note=comment)
    ContentArticleOperationLog.objects.create(
        article=article,
        operator=user,
        action="publish",
        from_status=old_status,
        to_status=article.status,
        comment=comment,
    )
    write_audit_log(...)
    invalidate_article_cache(article)
    return version
```

1. `title`、`slug`、`locale`、`content` 必填。
2. `content_format` 只能是 `markdown`。

1. 科普文章详情页是否支持系统字体放大。
2. VoiceOver/TalkBack 是否能正确朗读标题、发布时间、正文、参考来源。
3. 分享按钮、返回按钮、分类筛选是否有可访问名称。
4. 图片是否有替代文本策略。
5. 颜色对比是否满足 WCAG AA。

建议提问：

```text
使用 $无障碍检查员，审查 App 科普模块的列表页、详情页、Markdown 内容、分享按钮和参考来源区域，输出移动端无障碍验收清单。
```

1. 无障碍问题清单。
2. WCAG 对应条目。
3. VoiceOver/TalkBack 测试流程。

## 24.5 接口测试与联调

## 24.9 不建议优先使用的技能

以下技能当前不是科普模块客户端一期的首选，但在特定场景可使用：

| 技能名 | 暂不优先的原因 | 可使用场景 |
| --- | --- | --- |
| `$前端页面工程师` | 当前重点是 App 客户端，不是 Web 页面 | 后续实现 Web 分享落地页或后台管理 Web 页面 |
| `$后端接口架构师` | 本文已覆盖后端接口细化，除非进入后端实现 | 后续正式开发 `content` app、数据库、API 性能优化 |
| `$数据库优化工程师` | 一期数据量未必需要专项优化 | 文档量达到 10 万以上、列表/搜索变慢、阅读事件表增长过快 |
| `$部署运维工程师` | 一期不是部署运维问题 | 上线前配置缓存、限流、Celery 定时发布、监控告警 |
| `$代码审查员` | 适合代码完成后使用，不适合需求初稿阶段 | PR 合并前做代码审查 |
