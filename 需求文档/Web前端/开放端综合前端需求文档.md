# 一、背景与目标

## 1.1 业务背景

文档/文章系统已经具备后台创建、编辑、发布、下架、分类、标签、参考来源和公开接口能力。App 内用户点击分享后，需要生成一个可在浏览器打开的 Web 页面，而不是只返回 JSON 接口。

当前后端公开接口已经支持：

| 能力 | 接口 |
| --- | --- |
| 文章详情 | `GET /api/v1/content/articles/{slug}/?locale=zh-CN` |
| 文章列表 | `GET /api/v1/content/articles/?locale=zh-CN` |
| 点击量记录 | `POST /api/v1/content/articles/{id}/view/` |
| 阅读时长上报 | `POST /api/v1/content/articles/{id}/reading-duration/` |
| 分类列表 | `GET /api/v1/content/categories/` |
| 标签列表 | `GET /api/v1/content/tags/` |

因此 Web 分享页面一期重点是前端展示层建设：通过 `slug` 拉取文章详情，将 Markdown 正文安全渲染为 HTML，并提供适合手机浏览器、微信内置浏览器和桌面浏览器的阅读体验。

## 1.2 建设目标

一期目标：

1. 支持通过 `/content/:slug?locale=zh-CN` 打开文章详情。
2. 支持 Markdown 正文渲染，展示标题、摘要、发布时间、分类、标签、参考来源。
3. 支持移动端优先的阅读版式，兼容桌面浏览器。
4. 支持公开访问，无需登录。
5. 支持文章点击量记录和阅读时长上报。
6. 支持 App 分享落地，包括微信、短信、浏览器、系统分享面板打开。
7. 支持基础 SEO 元信息：`title`、`description`、Open Graph、Twitter Card 预留。
8. 支持 404、下架、私密内容不可访问等异常状态展示。
9. 保证 Markdown HTML 渲染安全，必须进行 XSS 清洗。
10. 复用当前已验证的 Vue 技术栈和工程习惯，降低新项目初始化成本。

## 1.3 综合前端定位

后续开放端页面会越来越多，如果按 `content-web`、`share-web`、`legal-web` 逐个拆项目，会造成路由、样式、构建、部署、埋点、错误页、SEO、App 唤起能力重复建设。因此统一建设一个综合前端：

```text
open-web
  - content 内容文章模块，一期实现
  - share 通用分享落地模块，后续接入，当前不实现
  - legal 协议与政策模块，后续预留
  - help 帮助中心模块，后续预留
  - campaign 活动落地页模块，后续预留
  - download App 下载与唤起模块，后续预留
```

`open-web` 与 `backoffice-web` 的边界：

| 前端 | 用户 | 是否登录 | 核心职责 |
| --- | --- | --- | --- |
| `backoffice-web` | 管理员、运营、客服 | 需要 | 内容生产、配置、审核、数据查看 |
| `open-web` | App 用户、被分享用户、搜索访问用户 | 不需要 | 内容展示、分享落地、协议帮助、App 唤起 |

命名规则：

1. 项目级只保留 `open-web`，不再新增 `content-web`、`share-web` 这类独立项目名。
2. 功能级使用子模块：`modules/content`、`modules/share`、`modules/legal`。
3. 路由级使用业务前缀：内容模块使用 `/content/*`，分享模块使用 `/share/*`，协议模块使用 `/legal/*`。
4. 公共能力沉淀到 `shared`，例如 Markdown 渲染、SEO Meta、分享、App 唤起、错误页、埋点。

## 1.4 非目标范围

一期不做：

1. 不做完整营销官网。
2. 不做用户登录、评论、点赞、收藏。
3. 不做复杂内容专题页、频道页和推荐流。
4. 不做 SSR 服务端渲染；SEO 先做基础 Meta 动态更新，后续如强 SEO 再评估 SSR/SSG。
5. 不做内容编辑能力，编辑仍在后台文章模块完成。
6. 不做付费内容、会员可见内容。
7. 不做多租户主题装修。

# 二、用户角色与场景

## 2.1 用户角色

| 角色 | 说明 | 核心诉求 |
| --- | --- | --- |
| App 用户 | 从 App 内点击分享或自己打开文章 | 快速阅读、页面清晰、可继续打开 App |
| 被分享用户 | 从微信/短信/浏览器收到链接 | 不登录也能阅读文章内容 |
| 搜索访问用户 | 通过搜索或外部链接进入 | 能看到标题、摘要、正文和来源 |
| 内容运营 | 在后台复制分享链接后检查页面 | 确认 Markdown、来源、标题和摘要展示正确 |
| 医疗合规/客服 | 查看对外公开页面内容 | 确认参考来源可见、内容没有丢失 |

## 2.2 典型访问场景

| 场景 | 说明 |
| --- | --- |
| App 分享文章 | App 使用后端生成的 `share_url`，用户分享给好友 |
| 微信内置浏览器打开 | 页面需要移动端适配，正文可读，不能依赖 App 环境 |
| 桌面浏览器打开 | 页面居中展示，阅读宽度合理，不铺满宽屏 |
| 后台运营检查 | 管理员复制文章分享链接，直接在浏览器检查渲染结果 |
| 文章已下架 | 返回友好的不可访问页面，不展示正文 |
| slug 不存在 | 返回 404 内容不存在页面 |

# 四、功能需求

## 4.1 内容详情加载

### 触发方式

用户访问：

```text
/content/:slug?locale=zh-CN
```

前端调用：

```http
GET /api/v1/content/articles/{slug}/?locale=zh-CN
```

### 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `slug` | path | string | 是 | 文章随机码 |
| `locale` | query | string | 否 | 默认 `zh-CN` |

### 成功响应字段

| 字段 | 用途 |
| --- | --- |
| `id` | 阅读统计上报使用 |
| `title` | 页面标题、SEO title |
| `slug` | 当前文章 URL 随机码 |
| `locale` | 当前语言 |
| `summary` | 摘要、SEO description |
| `cover_image` | 封面图 |
| `category` | 分类展示 |
| `tags` | 标签展示 |
| `published_at` | 发布时间 |
| `estimated_reading_minutes` | 预计阅读时间 |
| `content` | Markdown 正文 |
| `content_format` | 一期固定 `markdown` |
| `source_url` | 来源链接 |
| `references_json` / `references` | 参考来源 |
| `seo_title` | SEO 标题，优先于 title |
| `seo_description` | SEO 描述，优先于 summary |
| `share_links` | 分享链接、App scheme、Universal Link |
| `share_url` | 当前分享 URL |

### 验收标准

1. 给定已发布、公开文章，页面可以正常展示正文。
2. 给定不存在 `slug`，页面展示 404 状态。
3. 给定已下架、私密或已删除文章，后端返回不可访问时页面展示友好错误。
4. 页面刷新后仍能通过 URL 重新加载内容。
5. `locale` 不传时默认中文。

## 4.2 Markdown 渲染

### 实现要求

项目已安装：

| 依赖 | 用途 |
| --- | --- |
| `markdown-it` | Markdown 转 HTML |
| `dompurify` | 清洗 HTML，防止 XSS |

渲染流程：

```text
Markdown 原文
  -> markdown-it 转 HTML
  -> DOMPurify 清洗 HTML
  -> v-html 渲染
```

### Markdown 支持范围

| 语法 | 一期支持 | 说明 |
| --- | --- | --- |
| 标题 H1-H4 | 是 | H1 在正文中降级样式，避免和页面标题冲突 |
| 段落 | 是 | 保持适合中文阅读的行高 |
| 加粗/斜体 | 是 | 基础 Markdown |
| 有序/无序列表 | 是 | 支持嵌套样式 |
| 引用块 | 是 | 用于提示和免责声明 |
| 表格 | 是 | 移动端横向滚动 |
| 链接 | 是 | 外链新窗口打开，添加 `rel="noopener noreferrer"` |
| 图片 | 是 | 图片自适应宽度，限制最大宽度 |
| 代码块 | 可选 | 健康科普少用，但保留基础样式 |
| HTML 原文 | 不直接信任 | 必须经过 DOMPurify |

### 安全要求

1. 禁止未经清洗的 `v-html`。
2. 清洗后移除 `script`、事件属性、危险协议。
3. 链接只允许 `http`、`https`、`mailto` 等安全协议。
4. 图片只允许 `http`、`https` 或可信 CDN 域名；如后端已校验，前端仍需容错。
5. 外链默认新窗口打开。

### 样式要求

1. 正文最大宽度建议 `720px` 到 `820px`。
2. 手机端左右边距建议 `20px`。
3. 中文正文行高建议 `1.75` 到 `1.9`。
4. 表格在移动端包裹横向滚动容器。
5. 图片 `max-width: 100%`，圆角不超过 `8px`。
6. 不使用后台系统的卡片化布局，阅读页面应清爽、连续。

## 4.3 参考来源展示

### 展示位置

正文结束后展示“参考来源”区块。

### 展示字段

| 字段 | 展示规则 |
| --- | --- |
| `title` | 优先展示 |
| `url` | 有 URL 时可点击 |
| `source` | 有则展示来源类型 |
| `published_at` | 有则展示发布日期 |

### 展示规则

1. `references` 不为空时展示参考来源列表。
2. `source_url` 不为空且不在 references 中时，作为补充来源展示。
3. 无参考来源时，健康科普文章不应发布；前端仍需容错，可隐藏该模块或展示“暂无参考来源”。
4. 外链打开新窗口。

## 4.4 点击量记录

### 触发时机

文章详情接口加载成功后，上报一次点击事件。

```http
POST /api/v1/content/articles/{id}/view/
```

请求体：

```json
{
  "locale": "zh-CN",
  "session_id": "browser_session_id",
  "client_platform": "web"
}
```

### 去重策略

一期前端做轻量去重：

1. 使用 `sessionStorage` 记录当前浏览会话已上报的文章 ID。
2. 同一 tab 内刷新不重复上报。
3. 新会话重新打开可以再次上报。

后端后续可基于 IP、UA、session_id 做更严格去重。

## 4.5 阅读时长上报

### 触发时机

用户离开页面、切换标签页隐藏、停留超过阈值时上报。

```http
POST /api/v1/content/articles/{id}/reading-duration/
```

请求体：

```json
{
  "locale": "zh-CN",
  "duration_seconds": 35,
  "session_id": "browser_session_id",
  "client_platform": "web"
}
```

### 统计规则

1. 页面可见时才累计阅读时长。
2. 页面隐藏时暂停计时。
3. 最短上报阈值建议 5 秒。
4. 单次最大上报值遵循后端限制，当前后端会做上限裁剪。
5. 优先使用 `navigator.sendBeacon`，不支持时降级为普通 POST。

## 4.6 分享能力

### 页面内分享

一期提供一个“分享”按钮：

1. 支持 Web Share API 的浏览器调用 `navigator.share()`。
2. 不支持时复制当前链接到剪贴板。
3. 复制成功后提示“链接已复制”。

### 打开 App

页面顶部或底部可提供“打开 App”按钮：

1. 优先使用接口返回的 `share_links.app_scheme_url`。
2. 点击后尝试唤起 App。
3. 无法唤起时停留当前页面，不阻塞阅读。
4. 后续可接 Universal Link / App Link。

## 4.7 SEO 与社交分享 Meta

### 基础 Meta

文章加载成功后动态更新：

| Meta | 来源 |
| --- | --- |
| `document.title` | `seo_title || title` |
| `meta[name="description"]` | `seo_description || summary` |
| `og:title` | `seo_title || title` |
| `og:description` | `seo_description || summary` |
| `og:image` | `cover_image` |
| `og:type` | `article` |
| `og:url` | 当前 URL |
| `article:published_time` | `published_at` |

### 说明

Vite SPA 动态 Meta 对部分搜索引擎和社交抓取不稳定。一期作为基础 SEO 预留；如果后续强依赖微信卡片、搜索收录或社交平台预览，应升级为：

1. SSR：Vue SSR / Nuxt。
2. SSG：预渲染已发布文章。
3. 后端分享落地页模板：由 Django 输出完整 HTML Meta。

# 五、前端技术方案

## 5.1 open-web 建设原则

`open-web` 是面向用户开放访问的综合前端，定位类似 `backoffice-web` 的开放端对应物：`backoffice-web` 负责后台管理，`open-web` 负责公开页面、分享落地、协议帮助、活动落地和 App 唤起。

一期可以复用 `backoffice-web` 已验证的技术选型和工程习惯：

1. Vue 3 + TypeScript + Vite。
2. axios 请求封装。
3. `markdown-it` 和 `dompurify` 依赖。
4. 构建、预览、部署流程。
5. 文章 API 类型定义已存在。

但项目边界不再继续放进后台管理系统。建议新建或整理为统一 `open-web`，内部按子模块扩展。当前只实现 `content` 子模块；`share` 子模块后续接入，当前不实现。

## 5.2 本地开发端口约定

## 5.11 HTTP 封装

文件：`open-web/src/shared/api/http.ts`

参考 `backoffice-web/src/api/http.ts` 的响应解包方式，但开放端不携带管理员 token。

```ts
import axios, { AxiosError } from 'axios';

export interface ApiEnvelope<T> {
  code: number;
  msg: string | Record<string, unknown>;
  data: T;
}

const baseURL = import.meta.env.VITE_API_BASE_URL || '';

const http = axios.create({
  baseURL,
  timeout: 15000,
});

function toDisplayError(error: AxiosError): Error {
  const body = error.response?.data as Record<string, unknown> | undefined;
  const msg = body?.msg;
  if (typeof msg === 'string' && msg) return new Error(msg);
  if (error.response?.status === 404) return new Error('not_found');
  if (error.message) return new Error(error.message);
  return new Error('request_failed');
}

http.interceptors.response.use(
  (response) => {
    const payload = response.data as ApiEnvelope<unknown>;
    if (payload && typeof payload.code === 'number') {
      if (payload.code !== 0) {
        return Promise.reject(new Error(typeof payload.msg === 'string' ? payload.msg : 'request_failed'));
      }
      return payload.data;
    }
    return response.data;
  },
  (error: AxiosError) => Promise.reject(toDisplayError(error)),
);

export default http;
```

要求：

1. 不读取 `admin_access_token`。
2. 不做 refresh token。
3. 不自动跳转 `/login`。
4. 404、网络错误、业务错误交给页面状态处理。

## 5.14 Markdown 渲染实现细节

文件：`open-web/src/modules/content/components/ContentArticleMarkdown.vue`

推荐实现：

```vue
<script setup lang="ts">
import { computed } from 'vue';
import MarkdownIt from 'markdown-it';
import DOMPurify from 'dompurify';

const props = defineProps<{ content: string }>();

const md = new MarkdownIt({
  html: false,
  linkify: true,
  breaks: true,
});

const html = computed(() => {
```

## 5.15 阅读时长 Hook

文件：`open-web/src/shared/composables/useReadingDuration.ts`

核心逻辑：

1. 页面可见时累计秒数。
2. `visibilitychange` 为 hidden 时暂停并尝试上报。
3. `pagehide` / `beforeunload` 时使用 `sendBeacon` 上报。
4. 小于 5 秒不报。
5. 已上报的秒数需要清零，避免重复累计。

伪代码：

```ts
export function useReadingDuration(options: {
  articleId: () => number | null;
  locale: () => string;
  sessionId: string;
}) {
  let visibleAt = Date.now();
  let accumulated = 0;

  function pause() {
    if (document.visibilityState === 'visible') {
      accumulated += Math.floor((Date.now() - visibleAt) / 1000);
    }
  }

  function resume() {
    visibleAt = Date.now();
  }

  function flush() {
    const id = options.articleId();
    if (!id || accumulated < 5) return;
    // 优先 sendBeacon，失败再降级 axios
    accumulated = 0;
  }

  return { pause, resume, flush };
}
```

# 九、安全与合规

## 9.1 XSS 防护

必须做到：

1. Markdown 渲染后的 HTML 必须经过 `DOMPurify.sanitize()`。
2. 禁止直接渲染后端返回 HTML。
3. 禁止允许内联事件，例如 `onclick`。
4. 禁止危险协议，例如 `javascript:`。
5. 对外链添加 `rel="noopener noreferrer"`。

## 9.2 医疗健康免责声明

页面底部固定展示健康科普免责声明：

```text
本文为健康科普内容，不能替代医生诊断、治疗建议或用药指导。如有不适，请及时咨询专业医生。
```

## 9.3 参考来源

医疗健康内容必须展示参考来源，防止用户只看到结论看不到依据。

## 9.4 隐私

阅读统计一期不采集用户敏感信息。`session_id` 仅用于浏览会话级统计，不应包含手机号、用户 ID、设备号等敏感标识。

# 十二、验收标准

## 12.1 功能验收

1. 访问 `/content/jx9hdj8ickbk0xvb?locale=zh-CN` 可以看到文章页面。
2. 页面展示标题、摘要、发布时间、正文、参考来源。
3. Markdown 标题、列表、表格、引用、链接渲染正常。
4. 移动端 360px 宽度不横向溢出；表格除外，表格允许容器内横向滚动。
5. 点击外链在新窗口打开。
6. 不存在的 slug 展示 404 页面。
7. 已下架或私密文章不展示正文。
8. 页面加载成功后会调用点击量接口。
9. 页面停留并离开后会上报阅读时长。
10. 分享按钮在支持浏览器中调用系统分享，不支持时复制链接。

## 12.2 安全验收

1. Markdown 中注入 `<script>alert(1)</script>` 不执行。
2. Markdown 链接 `javascript:alert(1)` 不可执行。
3. 图片和链接不会撑破移动端布局。
4. 外链具备 `rel="noopener noreferrer"`。

## 12.3 构建验收

执行：

```bash
cd open-web
pnpm build
```

要求：

1. TypeScript 无错误。
2. Vite 构建成功。
3. 无新增阻塞性 lint/type 错误。

## 12.4 浏览器验收

| 浏览器 | 要求 |
| --- | --- |
| iOS Safari | 可读、可滚动、分享/复制可用 |
| Android Chrome | 可读、可滚动、分享/复制可用 |
| 微信内置浏览器 | 页面可打开，正文正常显示 |
| Desktop Chrome | 居中阅读，不铺满 |

## 13.2 open-web 独立工程建设条件

`open-web` 应作为开放端综合前端长期承载公开页面，不再拆出 `content-web`、`share-web` 等独立项目。满足任一条件时，应优先强化 `open-web` 的模块化、构建拆包、SSR/SSG 或部署能力，而不是按页面拆项目：

1. 开放 Web 页面超过 5 个以上。
2. 强依赖 SEO，需要 SSR/SSG。
3. 需要独立域名、独立发布节奏。
4. 需要面向 C 端的完整设计系统。
5. 后续接入 `share`、`legal`、`help`、`campaign`、`download` 等多个开放端模块。
