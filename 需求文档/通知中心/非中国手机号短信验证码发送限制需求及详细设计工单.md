# SparkService 非中国手机号短信验证码发送限制需求及详细设计工单

创建日期：2026-07-13  
关联模块：账户鉴权、手机号登录、短信 OTP、通知中心、移动客户端  
优先级：P1  
需求类型：能力边界控制 / 客户端体验调整 / 错误本地化 / 服务端风控

## 1. 背景

当前系统短信验证码发送能力仅支持中国手机号。手机号 OTP 入口为：

```http
POST /api/v1/otp/phone/request/
```

历史客户端为了规避不支持国际手机号的问题，默认隐藏了手机号登录 UI。但这会带来两个问题：

1. 能力边界被放在客户端控制，不利于多端一致。
2. 不同客户端版本、不同入口、不同灰度策略可能出现行为不一致。
3. 用户无法感知“当前仅支持中国手机号”，体验表现为入口缺失，而不是明确提示。
4. 后续如果服务端扩展海外短信供应商，客户端还需要重新发版打开入口。

因此本工单要求：**客户端不再负责控制手机号登录入口是否可见；手机号是否支持发送短信验证码由后台服务统一判断。**

## 2. 需求目标

1. 移动客户端默认展示手机号登录 UI，不再因为当前只支持中国手机号而隐藏入口。
2. 后台服务成为手机号短信验证码发送能力的唯一判定方。
3. 当用户输入非中国区号手机号并请求发送验证码时，服务端直接返回明确错误，不创建 OTP，不调用通知中心，不调用阿里云。
4. 错误响应必须支持客户端本地化，`msg` 返回稳定错误 key，客户端按 key 映射中英文等多语言文案。
5. 错误响应保留可排查数据，例如标准化手机号、区号、支持的国家/地区代码、`request_id`。
6. 本期不接入海外短信供应商，不支持非中国手机号真实发送。

## 3. 范围

### 3.1 本期做

1. 客户端手机号登录 UI 默认展示。
2. 服务端在手机号 OTP 请求阶段识别手机号国家/区号。
3. 服务端仅允许中国手机号进入短信发送链路。
4. 非中国区号手机号直接返回本地化错误 key。
5. 后台日志记录拦截原因，便于统计海外手机号需求量。
6. 自动化测试覆盖中国手机号放行、非中国手机号拦截、错误响应结构。

### 3.2 本期不做

1. 不接入 Twilio、阿里云国际短信、腾讯云国际短信等海外供应商。
2. 不支持非中国手机号注册、登录、注销验证码发送。
3. 不让客户端通过配置白名单自行放开海外手机号。
4. 不在本工单中调整邮箱登录、Apple 登录、微信登录等其他登录方式。
5. 不迁移历史 OTP 或通知中心数据。

## 4. 产品规则

### 4.1 客户端展示规则

| 项目 | 规则 |
|---|---|
| 手机号登录入口 | 默认展示 |
| 区号选择 | 可展示国家/区号选择器，或至少允许用户输入 E.164 格式手机号 |
| 是否允许点击发送验证码 | 客户端不以区号作为强控制条件 |
| 发送失败展示 | 使用服务端 `msg` 做本地化映射 |
| 诊断信息 | `data.reason`、`data.request_id` 只用于日志、客服排查或调试页 |

推荐客户端文案：

| 服务端 `msg` | 中文文案 | 英文文案 |
|---|---|---|
| `phone_region_not_supported` | 当前仅支持中国大陆手机号接收短信验证码 | SMS verification is currently available for mainland China phone numbers only. |

### 4.2 服务端控制规则

服务端按标准化后的 E.164 手机号判断区号：

| 手机号示例 | 判定 | 处理 |
|---|---|---|
| `+8613800138000` | 中国手机号 | 继续进入 OTP 和短信发送链路 |
| `13800138000` | 可按中国手机号解析 | 继续进入 OTP 和短信发送链路 |
| `+85251234567` | 非中国大陆区号 | 拦截，返回 `phone_region_not_supported` |
| `+14155552671` | 非中国大陆区号 | 拦截，返回 `phone_region_not_supported` |
| `+819012345678` | 非中国大陆区号 | 拦截，返回 `phone_region_not_supported` |
| 非法号码 | 格式错误 | 返回现有 `invalid_phone_number` |

> 说明：本工单中的“中国手机号”指当前服务端短信供应商配置可支持的中国大陆手机号能力，即 `+86`。港澳台及其他国家/地区手机号本期均视为不支持短信验证码发送。

## 5. 接口设计

### 5.1 请求接口

接口不变：

```http
POST /api/v1/otp/phone/request/
```

请求示例：

```json
{
  "phone_number": "+14155552671",
  "provider_uid": "",
  "scene": "login",
  "bundle_id": "cn.Zhaodk.Health",
  "device_id": "680783DA-E49E-4C68-BBE9-2939FFC7897F"
}
```

### 5.2 非中国手机号响应

HTTP 状态码建议使用 `400 Bad Request`。这是业务输入不在当前支持范围内，不是短信供应商失败，也不是登录态失败。

```json
{
  "code": 40033,
  "msg": "phone_region_not_supported",
  "data": {
    "error_type": "phone_region_not_supported",
    "reason": "phone_region_not_supported",
    "phone_region": "US",
    "dial_code": "+1",
    "supported_regions": ["CN"],
    "supported_dial_codes": ["+86"],
    "request_id": "AB49292E-55CD-45F1-B9A4-FFA5BD5911E0"
  }
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `code` | 业务错误码，建议新增 `40033` |
| `msg` | 稳定本地化 key，客户端用它做多语言映射 |
| `data.error_type` | 与 `msg` 保持一致，便于客户端兼容旧解析 |
| `data.reason` | 诊断原因，本场景与 `msg` 一致 |
| `data.phone_region` | 服务端识别出的国家/地区代码，识别不到可为空 |
| `data.dial_code` | 服务端识别出的区号，识别不到可为空 |
| `data.supported_regions` | 当前服务端支持的国家/地区 |
| `data.supported_dial_codes` | 当前服务端支持的区号 |
| `data.request_id` | 请求链路 ID |

### 5.3 与现有错误的关系

| 场景 | HTTP | code | msg |
|---|---:|---:|---|
| 手机号为空 | 400 | `40031` | `phone_number required` 或后续统一为 `phone_number_required` |
| 手机号格式非法 | 400 | `40032` | `invalid_phone_number` |
| 手机号格式合法但区号不支持 | 400 | `40033` | `phone_region_not_supported` |
| 请求过于频繁 | 429 | `42901` | `otp_requested_too_frequently` |
| 阿里云业务流控 | 429 | `42902` | `sms_send_rate_limited` |

## 6. 后端详细设计

### 6.1 校验位置

建议在 `OTPService.request_phone_otp` 中完成非中国手机号拦截，位置应在：

1. `PhoneNumberService.normalize_e164(phone_number)` 成功之后。
2. 查询最近 OTP 频控之前。
3. 创建 `PhoneOTP` 之前。
4. 调用 `NotificationCenterService.send_phone_otp` 之前。

推荐顺序：

```text
request_phone_otp
  -> normalize_e164(phone_number)
  -> resolve_phone_region(normalized_phone)
  -> if region not supported: raise APIError(phone_region_not_supported)
  -> cooldown check
  -> create PhoneOTP
  -> send_phone_otp
```

这样可以保证非中国手机号不会产生：

1. `PhoneOTP` 记录。
2. `NotificationIntent`。
3. `NotificationMessage`。
4. `ChannelDelivery`。
5. 阿里云发送请求。

### 6.2 区号识别

优先使用项目现有手机号解析能力。如果当前 `PhoneNumberService.normalize_e164` 已依赖 `phonenumbers`，则新增一个服务端方法：

```python
PhoneNumberService.resolve_region(normalized_phone) -> PhoneRegion
```

建议返回结构：

```python
PhoneRegion(
    region_code="CN",
    country_code=86,
    dial_code="+86",
    is_supported_for_sms_otp=True,
)
```

如果暂时不新增结构体，也可以用轻量方法：

```python
PhoneNumberService.is_supported_sms_otp_region(normalized_phone) -> bool
PhoneNumberService.get_region_code(normalized_phone) -> str
PhoneNumberService.get_dial_code(normalized_phone) -> str
```

### 6.3 支持区号配置

建议服务端配置化支持范围，默认只支持中国：

```dotenv
SMS_OTP_SUPPORTED_REGIONS=CN
SMS_OTP_SUPPORTED_DIAL_CODES=+86
```

配置规则：

1. 默认值为 `CN` / `+86`，保证不配置时维持当前能力边界。
2. 后续接入海外短信供应商时，可在服务端扩展配置，不需要客户端改控制逻辑。
3. 配置不应由客户端下发，也不应依赖客户端灰度开关。

### 6.4 APIError 设计

新增服务层错误：

```python
APIError(
    "phone_region_not_supported",
    code=40033,
    status_code=400,
    details={
        "error_type": "phone_region_not_supported",
        "reason": "phone_region_not_supported",
        "phone_region": region_code,
        "dial_code": dial_code,
        "supported_regions": supported_regions,
        "supported_dial_codes": supported_dial_codes,
    },
)
```

统一异常处理层负责补充 `request_id`。如果当前异常处理层尚未对 `details` 合并 `request_id`，应作为本工单实现内容之一。

### 6.5 日志与观测

非中国手机号被拦截时记录 warning 级别业务日志：

```text
auth.phone_otp.request.service.failed
reason=phone_region_not_supported
phone_region=US
dial_code=+1
bundle_id=cn.Zhaodk.Health
device_id=680783DA-E49E-4C68-BBE9-2939FFC7897F
request_id=...
```

日志要求：

1. 不输出完整手机号。
2. 可输出掩码手机号或 normalized phone hash。
3. 必须记录 `bundle_id`、`device_id`、`region`、`dial_code`、`request_id`。
4. 指标侧建议统计 `phone_region_not_supported` 次数，用于判断海外手机号登录需求。

## 7. 客户端详细设计

### 7.1 UI 调整

客户端默认展示手机号登录 UI：

1. 登录页展示手机号登录入口。
2. 不再因为当前只支持中国手机号而隐藏入口。
3. 区号选择器可保留或新增，但不作为最终发送能力判断。
4. 点击发送验证码后，以服务端响应为准。

### 7.2 错误展示

客户端本地化 key 映射：

```text
phone_region_not_supported -> 当前仅支持中国大陆手机号接收短信验证码
otp_requested_too_frequently -> 验证码请求过于频繁，请稍后再试
sms_send_rate_limited -> 短信发送过于频繁，请稍后再试
sms_send_failed -> 短信发送失败，请稍后重试
sms_send_unknown -> 短信发送结果暂时未知，请稍后重试
```

展示规则：

1. 优先按 `msg` 查本地化文案。
2. 如果 `msg` 没有命中文案表，展示通用错误文案。
3. `data.reason` 不直接面向普通用户展示，除非进入诊断模式或客服日志。
4. `data.request_id` 可复制或进入客服诊断信息。

## 8. 兼容性

1. 老客户端继续调用同一接口，不需要新增参数。
2. 老客户端如果只展示 `msg`，会看到 `phone_region_not_supported`，虽然不够友好，但不会误判成功。
3. 新客户端应按 `msg` 做本地化映射。
4. 服务端控制生效后，即使旧客户端隐藏入口，也不影响安全边界；新客户端展示入口后，非中国手机号仍由服务端拦截。

## 10. 验收标准

1. 手机号登录 UI 在客户端默认展示。
2. 中国手机号验证码发送不受影响。
3. 非中国区号手机号请求发送验证码时，服务端返回 `40033 phone_region_not_supported`。
4. 非中国手机号请求不会创建 OTP 或通知中心发送记录。
5. 非中国手机号请求不会调用阿里云短信接口。
6. 客户端能基于 `msg=phone_region_not_supported` 展示本地化文案。
7. 服务端日志可通过 `request_id` 查询到拦截原因。
8. 自动化测试覆盖服务端拦截和错误响应结构。

## 11. 风险与注意事项

1. 客户端打开手机号登录入口后，海外用户会更容易触达该能力，短期内 `phone_region_not_supported` 错误量可能上升。
2. 如果客户端没有及时接入本地化映射，用户可能看到错误 key；因此客户端发版需同步文案表。
3. 如果服务端仅用字符串前缀 `+86` 判断，需注意号码解析准确性；推荐使用成熟手机号解析库。
4. 港澳台手机号本期也会被拦截，产品和客服口径需要提前统一。
5. 后续接入海外短信供应商时，应扩展服务端支持配置和 Provider 路由，而不是重新把控制逻辑放回客户端。

## 12. 建议拆分任务

| 任务 | 负责人 | 说明 |
|---|---|---|
| 服务端手机号地区识别与拦截 | 后端 | 新增 `phone_region_not_supported` 错误 |
| OTP 请求链路测试 | 后端 | 覆盖非中国手机号不创建 OTP、不发短信 |
| 手机号登录入口默认展示 | iOS / Android | 去掉默认隐藏逻辑 |
| 客户端本地化文案 | iOS / Android | 增加 `phone_region_not_supported` 文案 |
| 联调验收 | 后端 + 移动端 | 使用 `+86`、`+1`、`+852` 三类号码验证 |
