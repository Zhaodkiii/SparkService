# SparkService 后台通知用户列表查询参数类型未转换导致 500 修复工单

创建日期：2026-07-16  
关联模块：通知中心、后台管理系统、通知用户列表、接口参数解析  
优先级：P0  
修复类型：接口参数类型错误 / 后台列表不可用 / 服务端 500

## 1. 背景

后台管理系统请求通知中心用户列表接口：

```http
GET /api/admin/v1/notification-center/notifications/users/?page=1&page_size=20&q=&only_enabled=true
```

服务端返回：

```json
{
  "code": -1,
  "msg": "Internal Server Error",
  "data": {
    "request_id": "25f00c7b-a316-4f04-b0ae-4dd2271a2886"
  }
}
```

对应异常：

```text
TypeError: unsupported operand type(s) for -: 'str' and 'int'
```

异常位置：

```text
notification_center/services.py:607
offset = max(page - 1, 0) * page_size
```

## 2. 问题现象

### 2.1 后台页面表现

1. 管理员进入通知中心的通知用户列表页面。
2. 前端发起用户列表查询，请求携带 `page=1&page_size=20&q=&only_enabled=true`。
3. 接口返回 500。
4. 页面无法正常展示可通知用户列表。

### 2.2 日志表现

```text
INFO HTTP 请求进入: GET /api/admin/v1/notification-center/notifications/users/
ERROR Unhandled exception GET /api/admin/v1/notification-center/notifications/users/
TypeError: unsupported operand type(s) for -: 'str' and 'int'
ERROR HTTP 响应摘要: status=500 body={"code": -1, "msg": "Internal Server Error", ...}
```

## 3. 根因分析

### 3.1 视图层原样透传 query params

当前入口位于 `notification_center/views.py`：

```python
class AdminNotificationUserListView(APIView):
    permission_classes = [AdminOnlyPermission]

    def get(self, request):
        result = NotificationCenterService.list_notification_users(**request.query_params.dict())
        return success_response(result, msg="success", code=0, status_code=status.HTTP_200_OK)
```

`request.query_params.dict()` 取出的值全部是字符串，因此实际传入服务层的是：

```python
{
    "page": "1",
    "page_size": "20",
    "q": "",
    "only_enabled": "true",
}
```

### 3.2 服务层只做了类型标注，没有做运行时转换

当前服务方法签名位于 `notification_center/services.py`：

```python
def list_notification_users(
    *,
    q: str = "",
    page: int = 1,
    page_size: int = 20,
    only_enabled: bool = True,
    has_email: bool | None = None,
    has_sms: bool | None = None,
    has_apns: bool | None = None,
    is_active: bool | None = None,
) -> dict[str, Any]:
```

虽然 `page` 和 `page_size` 标注为 `int`，但 Python 不会自动转换请求字符串。接口传入 `"1"` 后，在分页计算处执行：

```python
offset = max(page - 1, 0) * page_size
```

就会触发：

```text
unsupported operand type(s) for -: 'str' and 'int'
```

### 3.3 布尔筛选也存在潜在逻辑错误

`only_enabled=true` 同样以字符串形式进入服务层。当前 `_filter_user_queryset` 中判断：

```python
if only_enabled:
    queryset = queryset.filter(NotificationCenterService._q_user_has_any_notifiable_channel())
```

字符串 `"false"` 在 Python 中也是 truthy，因此如果前端传：

```http
only_enabled=false
```

后端仍会按 `True` 处理，导致筛选结果与页面选择不一致。

同类风险还包括：

- `has_email=true/false`
- `has_sms=true/false`
- `has_apns=true/false`
- `is_active=true/false`

这些参数在服务层使用的是 `is True / is False` 精确判断，如果未转换为布尔值，就会被当作未传过滤条件处理。

## 4. 影响范围

1. 后台通知中心用户列表接口直接 500，页面不可用。
2. 批量选择通知目标用户的前置列表无法加载。
3. 通知中心按用户发送、筛选可通知用户等后台操作受阻。
4. 即使修复分页 500，如果不处理布尔参数，筛选条件仍可能 silently wrong。

## 5. 修复目标

1. 后台通知用户列表接口不能因为字符串 query params 返回 500。
2. `page`、`page_size` 必须转换为合法整数，并限制异常值。
3. `only_enabled`、`has_email`、`has_sms`、`has_apns`、`is_active` 必须按明确布尔语义解析。
4. 非法参数应返回 400 和可读错误，不应进入服务层后抛未处理异常。
5. 服务层保留对直接调用的防御性转换，避免未来新增入口重复踩坑。

## 6. 修复方案

### 6.1 推荐方案：在视图层使用 DRF Serializer 校验查询参数

新增一个查询参数 Serializer，例如：

```python
class AdminNotificationUserListQuerySerializer(serializers.Serializer):
    q = serializers.CharField(required=False, allow_blank=True, default="")
    page = serializers.IntegerField(required=False, min_value=1, default=1)
    page_size = serializers.IntegerField(required=False, min_value=1, max_value=100, default=20)
    only_enabled = serializers.BooleanField(required=False, default=True)
    has_email = serializers.BooleanField(required=False, allow_null=True)
    has_sms = serializers.BooleanField(required=False, allow_null=True)
    has_apns = serializers.BooleanField(required=False, allow_null=True)
    is_active = serializers.BooleanField(required=False, allow_null=True)
```

视图层改为：

```python
serializer = AdminNotificationUserListQuerySerializer(data=request.query_params)
serializer.is_valid(raise_exception=True)
result = NotificationCenterService.list_notification_users(**serializer.validated_data)
```

这样：

- `page=1` 会变成 `int(1)`
- `page_size=20` 会变成 `int(20)`
- `only_enabled=true` 会变成 `True`
- `only_enabled=false` 会变成 `False`
- 非法值由 DRF 统一返回 400

### 6.2 服务层增加兜底归一化

为了防止其他调用方继续传字符串，建议 `list_notification_users` 入口保留防御性处理：

```python
page = max(int(page or 1), 1)
page_size = min(max(int(page_size or 20), 1), 100)
```

布尔参数建议抽一个内部 helper，支持：

- `True / False`
- `"true" / "false"`
- `"1" / "0"`
- `"yes" / "no"`
- 空字符串按默认或 `None` 处理

注意：视图层校验是主方案，服务层兜底是防未来误用。

### 6.3 修复分页返回值

修复后分页返回应始终为数字：

```json
{
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 123,
    "total_pages": 7
  }
}
```

不能把 `"1"`、`"20"` 字符串继续透出给前端。

### 6.4 统一同类后台列表接口的参数处理

同文件中其他列表接口已经存在局部手写转换，例如：

```python
page = int(request.query_params.get("page") or 1)
page_size = int(request.query_params.get("page_size") or 50)
```

建议逐步统一为 Serializer 校验，至少本次应检查通知中心后台接口中是否还有类似：

```python
service_method(**request.query_params.dict())
```

如存在，应同步纳入修复或创建后续治理任务。

## 7. 回归测试建议

### 7.1 接口成功场景

请求：

```http
GET /api/admin/v1/notification-center/notifications/users/?page=1&page_size=20&q=&only_enabled=true
```

期望：

- HTTP 200
- `code=0`
- 返回 `items`
- 返回数字类型分页字段

### 7.2 布尔筛选场景

分别测试：

```http
only_enabled=true
only_enabled=false
has_email=true
has_email=false
has_sms=true
has_sms=false
has_apns=true
has_apns=false
is_active=true
is_active=false
```

期望：

- 参数能正确解析为布尔值。
- `false` 不得被 Python truthy 字符串误判为 `True`。
- 三态筛选参数未传时不应额外过滤。

### 7.3 非法参数场景

请求：

```http
GET /api/admin/v1/notification-center/notifications/users/?page=abc&page_size=20
```

期望：

- HTTP 400
- 返回明确参数错误
- 不产生 500

请求：

```http
GET /api/admin/v1/notification-center/notifications/users/?page=1&page_size=10000
```

期望：

- 要么返回 400
- 要么按上限裁剪到 `100`
- 不允许无限大分页拖垮接口

## 8. 验收标准

1. 复现日志中的请求重新调用后返回 200。
2. 后台通知用户列表页面能正常加载。
3. 服务端日志不再出现 `unsupported operand type(s) for -: 'str' and 'int'`。
4. `only_enabled=false` 能正确返回未强制过滤可通知渠道的用户范围。
5. `has_email/has_sms/has_apns/is_active` 的 true/false 筛选结果符合预期。
6. 非法分页参数返回 400，不返回 500。
7. 新增或更新自动化测试覆盖本次崩溃请求和布尔参数解析。
