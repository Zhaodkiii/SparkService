# SparkService 客户端默认隐藏手机号登录 UI 改为不隐藏需求工单

创建日期：2026-07-13  
关联模块：移动客户端、账户登录、手机号登录入口、短信 OTP  
优先级：P1  
需求类型：客户端交互调整 / 登录入口放开 / 能力控制下沉

## 1. 背景

当前移动客户端为了规避“仅支持中国手机号短信验证码发送”的限制，默认隐藏了手机号登录 UI。

这导致几个问题：

1. 登录能力是否可见由客户端控制，而不是由服务端统一控制。
2. 用户看不到手机号登录入口，无法形成明确预期。
3. 不同客户端版本可能出现一部分显示、一部分隐藏的分裂行为。
4. 后续如果服务端支持更多手机号区域，客户端还需要再次发版放开入口。

当前服务端已经逐步承担手机号能力边界控制，因此客户端不应再通过隐藏 UI 的方式承担这部分职责。

## 2. 需求目标

1. 客户端默认展示手机号登录 UI。
2. 手机号登录入口不再因“当前只支持中国手机号”而隐藏。
3. 用户是否能成功发送验证码，由服务端接口结果决定。
4. 客户端只负责：
   - 展示手机号登录入口
   - 收集手机号
   - 发起验证码请求
   - 根据服务端 `msg` 做本地化错误展示
5. 本工单仅处理客户端 UI 默认隐藏改为不隐藏，不修改服务端发送能力边界。

## 3. 范围

### 3.1 本期做

1. 登录页手机号登录入口默认展示。
2. 原有隐藏开关、默认 `hidden` 状态、条件渲染逻辑调整为默认可见。
3. 客户端继续调用现有：

```http
POST /api/v1/otp/phone/request/
```

4. 接口失败时按服务端返回的 `msg` 做本地化提示。

### 3.2 本期不做

1. 不修改服务端短信发送逻辑。
2. 不新增海外手机号发送能力。
3. 不在本工单中增加新的登录方式。
4. 不调整账号注册、Apple 登录、邮箱登录等其他入口布局。
5. 不在本工单中设计新的风控逻辑。

## 4. 产品规则

### 4.1 UI 规则

| 项目 | 规则 |
|---|---|
| 手机号登录入口 | 默认显示 |
| 入口位置 | 保持当前登录页信息架构，不新增二级页面 |
| 是否根据区号隐藏 | 否 |
| 是否根据国家/地区隐藏 | 否 |
| 是否根据服务端配置隐藏 | 否，客户端仅展示入口 |
| 是否允许点击发送验证码 | 允许，发送结果以服务端返回为准 |

### 4.2 服务端协作规则

客户端展示手机号登录入口后，实际可用性由服务端控制：

| 场景 | 客户端行为 | 服务端行为 |
|---|---|---|
| 中国手机号 | 展示入口并允许发送 | 正常进入 OTP 流程 |
| 非中国区号手机号 | 展示入口并允许发送 | 返回 `phone_region_not_supported` |
| 手机号格式错误 | 展示入口并允许发送 | 返回 `invalid_phone_number` |
| 请求过于频繁 | 展示入口并允许发送 | 返回 `otp_requested_too_frequently` |

因此客户端职责是“展示和响应”，不是“预先拦截和隐藏”。

## 5. 客户端详细设计

### 5.1 可见性调整

当前默认隐藏手机号登录 UI 的逻辑需要改为默认显示，常见实现可能包括：

1. 功能开关默认值为 `false -> true`
2. 视图层 `isPhoneLoginHidden = true -> false`
3. 条件渲染从：

```text
if supportPhoneLogin then show
else hide
```

改为：

```text
always show phone login entry
```

4. 仅在极端异常场景保留兜底隐藏，例如页面资源未加载完成，但不再因为“当前仅支持中国手机号”而隐藏。

### 5.2 交互规则

客户端流程：

1. 展示手机号登录 UI。
2. 用户输入手机号并点击发送验证码。
3. 调用服务端 OTP 请求接口。
4. 根据返回结果处理：
   - `code=0`：进入验证码输入态
   - 非 `0`：按 `msg` 映射本地化文案并提示用户

### 5.3 错误提示规则

客户端不直接展示服务端原始 `reason` 给普通用户，优先按 `msg` 做本地化。

建议映射：

| `msg` | 中文文案 |
|---|---|
| `phone_region_not_supported` | 当前仅支持中国大陆手机号接收短信验证码 |
| `invalid_phone_number` | 请输入正确的手机号 |
| `otp_requested_too_frequently` | 验证码请求过于频繁，请稍后再试 |
| `sms_send_rate_limited` | 短信发送过于频繁，请稍后再试 |
| `sms_send_failed` | 短信发送失败，请稍后重试 |
| `sms_send_unknown` | 短信发送结果暂时未知，请稍后重试 |

## 6. 兼容性

1. 老服务端仍可继续处理手机号 OTP 请求，不依赖客户端隐藏入口。
2. 新客户端放开入口后，不会绕过服务端能力边界。
3. 即使用户输入非中国手机号，也会由服务端返回明确错误，不会误发送。
4. 客户端发版后，老版本仍可能继续隐藏入口，这是版本差异，不影响服务端控制正确性。

## 7. 验收标准

1. 登录页手机号登录入口默认可见。
2. 不再因为“仅支持中国手机号”而隐藏手机号登录 UI。
3. 用户输入中国手机号时，可正常请求验证码。
4. 用户输入非中国区号手机号时，客户端可收到服务端错误并正确提示。
5. 客户端错误展示基于 `msg` 做本地化，而不是写死服务端文案。
6. 入口展示后，不影响邮箱登录、Apple 登录等现有入口。

## 8. 测试建议

### 8.1 客户端测试

1. 登录页默认展示手机号登录入口。
2. 冷启动、热启动、切换语言后入口仍显示。
3. 中国手机号发送验证码流程正常。
4. 输入 `+852`、`+1` 等非中国区号手机号时，收到服务端错误并展示正确提示。
5. 服务端返回 `otp_requested_too_frequently`、`sms_send_rate_limited` 时，客户端提示正确。
