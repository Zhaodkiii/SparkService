## 工单 `BACKOFFICE-000001`：用户管理增加用户详情弹窗

### 1. 背景

当前后台管理已有用户管理入口：

- 菜单位置：`backoffice-web/src/layouts/AdminLayout.vue:80-89`
- 页面路由：`/users`
- 页面文件：`backoffice-web/src/views/UsersView.vue`

现有用户管理列表展示字段为：

| ID | 用户名 | 邮箱 | 状态 | 操作 |
| --- | --- | --- | --- | --- |

当前操作列仅支持启用/禁用：

- 页面位置：`backoffice-web/src/views/UsersView.vue:20-28`
- 接口位置：`backoffice-web/src/api/modules/users.ts:69-71`
- 服务端接口：`POST /api/admin/v1/users/{user_id}/status/`

随着账号设备登录、可信设备、单设备登录会话能力完善，后台需要能快速查看某个用户的完整账号信息、设备登记信息、登录会话流水，方便排查：

1. 用户是否被禁用。
2. 当前用户有哪些设备记录。
3. 哪台设备是当前有效登录设备。
4. 旧设备是否已失效。
5. APNs 推送 token、通知权限、国家/地区等设备画像是否正常。
6. `TrustedDevice` 与 `AccountDeviceSession` 状态是否一致。

### 2. 目标

1. 用户管理列表操作列增加“详细”按钮。
2. 点击“详细”后弹窗展示用户详情。
3. 详情弹窗参考试用详情弹窗样式：
   - `backoffice-web/src/views/AITrialsView.vue:61-117`
4. 详情弹窗内展示：
   - 用户基础信息。
   - 登录设备信息：`TrustedDevice`。
   - 登录会话流水：`AccountDeviceSession`。
5. 详情弹窗样式建议抽成公共组件，在后台项目内统一复用，避免 `AITrialsView.vue`、用户详情、后续其它详情弹窗重复维护相同结构。

### 3. 用户列表改动

#### 3.1 列表字段

用户管理列表保持现有字段：

| 字段 | 说明 | 当前来源 |
| --- | --- | --- |
| ID | 用户 ID | `AdminUser.id` |
| 用户名 | 用户名 | `AdminUser.username` |
| 邮箱 | 邮箱 | `AdminUser.email` |
| 状态 | 启用/禁用 | `AdminUser.is_active` |
| 操作 | 禁用/启用、详细 | 页面操作列 |

#### 3.2 操作列

操作列新增“详细”按钮：

| 按钮 | 展示条件 | 行为 |
| --- | --- | --- |
| 详细 | 有用户列表查看权限即可展示 | 打开用户详情弹窗 |
| 禁用/启用 | `button:user:status:update` | 调用现有状态更新接口；禁用必须二次确认 |

建议顺序：

1. 详细
2. 禁用/启用

如同时执行“后台表格操作列悬浮统一需求文档”，用户管理页操作列需要使用统一右侧悬浮操作列组件，避免单独维护列宽和 hover actions。

#### 3.3 禁用二次确认

用户管理中的“禁用”属于高风险操作，点击后必须使用项目内通用确认弹窗进行二次确认，不能直接调用状态更新接口。

参考现有实现：

- `backoffice-web/src/views/VersionConfigsView.vue:184-191`
- 使用 `Modal.confirm`

交互要求：

1. 点击“禁用”后弹出二次确认弹窗。
2. 弹窗标题建议：`禁用用户`
3. 弹窗内容需要明确风险，例如：`禁用后该用户将无法继续登录和使用 App，确定要禁用吗？`
4. 用户点击确认后才调用 `updateUserStatus(userId, false)`。
5. 用户点击取消时不发起接口请求。
6. “启用”可直接执行，也可以使用轻量确认；本期强制要求“禁用”必须二次确认。
7. 确认弹窗需要复用项目内通用方式，不在页面内自定义一套新的弹窗样式。

### 5. 用户详情展示内容

#### 5.1 用户基础信息

使用 `a-descriptions` 展示：

| 字段 | 说明 |
| --- | --- |
| 用户 ID | Django User 主键 |
| 用户名 | `username` |
| 邮箱 | `email` |
| 状态 | 启用/禁用，使用 tag |
| 是否 Staff | `is_staff` |
| 是否 Superuser | `is_superuser` |
| 注册时间 | `date_joined` |
| 最近登录 | `last_login` |

如服务端已有手机号、Apple 用户标识、账号注销状态等扩展信息，可后续补充；本期优先展示已有 `AdminUserSerializer` 可稳定提供的数据。

#### 5.2 登录设备信息：TrustedDevice

使用表格展示该用户所有 `TrustedDevice` 记录，按 `last_seen desc, id desc` 排序。

建议展示字段：

| 字段 | 说明 |
| --- | --- |
| ID | `TrustedDevice.id` |
| device_id | 安装级设备 ID |
| bundle_id | 应用包维度 |
| 平台 | `platform` |
| 系统版本 | `system_version` |
| 设备型号 | `device_model` / `device_model_name` |
| 设备名称 | `device_name` |
| 通知权限 | `notifications_enabled` |
| push_token | 建议脱敏展示，默认只展示前后若干位 |
| 国家/地区 | `country_code` / `region_code` |
| 语言 | `language_code` |
| 是否模拟器 | `is_simulator` |
| 是否失效 | `is_revoked`，使用 tag |
| 首次登记 | `first_seen` |
| 最近上报 | `last_seen` |
| request_id | 最近一次登记链路 |

注意点：

1. 同一用户可能存在多条设备记录。
2. 旧设备被新设备替换后，`TrustedDevice.is_revoked` 应展示为失效。
3. 设备详情是排查 APNs 与单设备登录问题的重要入口，不应只展示最近一条。
4. `push_token` 属于敏感字段，列表默认脱敏；如后续需要复制完整值，应加权限控制。

#### 5.3 登录会话流水：AccountDeviceSession

使用表格展示该用户所有 `AccountDeviceSession` 记录，按 `updated_at desc, id desc` 排序。

建议展示字段：

| 字段 | 说明 |
| --- | --- |
| ID | `AccountDeviceSession.id` |
| trusted_device_id | 关联设备 ID |
| device_id | 登录时设备 ID 快照 |
| bundle_id | 登录时 bundle 快照 |
| 状态 | `active` / `revoked` / `logged_out`，展示中文 tag |
| 会话版本 | `session_version` |
| 失效原因 | `revoked_reason` |
| 替换会话 | `replaced_by` |
| 最近刷新 | `last_refreshed_at` |
| 创建时间 | `created_at` |
| 更新时间 | `updated_at` |

状态中文建议：

| 原值 | 展示 |
| --- | --- |
| `active` | 有效 |
| `revoked` | 已失效 |
| `logged_out` | 已退出 |

注意点：

1. 当前有效登录设备应以 `AccountDeviceSession.status=active` 为准。
2. `TrustedDevice.is_revoked=false` 不等于一定是当前登录设备；判断当前登录态需要看 active session。
3. 登录新设备后，旧 session 应变为 `revoked`。
4. 主动退出后，session 应变为 `logged_out`。

## 工单 `BACKOFFICE-000002`：后台时间展示统一为中国常用格式

### 1. 背景

当前 `backoffice-web` 中不少时间字段直接展示服务端返回的 ISO8601 字符串，例如：

```text
2026-05-07T03:59:31.951067Z
```

这种格式适合接口传输和机器解析，但不适合后台管理人员阅读。后台页面应统一展示为中国常用时间格式，避免不同页面出现：

1. ISO8601 原始格式。
2. 浏览器默认 `toLocaleString()` 格式。
3. 各页面自行拼接的不同格式。
4. 空值展示不统一。

### 2. 目标

1. `backoffice-web` 内所有时间展示统一格式。
2. 服务端继续返回 ISO8601，不要求改后端字段格式。
3. 前端新增公共时间格式化工具或组件，所有页面统一使用。
4. 空值统一展示 `-`。
5. 日期时间统一使用中国常用格式：

```text
YYYY-MM-DD HH:mm:ss
```

示例：

```text
2026-05-07 11:59:31
```

说明：服务端返回 `2026-05-07T03:59:31.951067Z` 时，前端按浏览器本地时区展示；中国大陆后台环境下应显示为北京时间 `2026-05-07 11:59:31`。

### 3. 格式规范

| 类型 | 展示格式 | 示例 |
| --- | --- | --- |
| 日期时间 | `YYYY-MM-DD HH:mm:ss` | `2026-05-07 11:59:31` |
| 仅日期 | `YYYY-MM-DD` | `2026-05-07` |
| 空值 | `-` | `-` |
| 非法时间 | `-` 或原值兜底 | 优先 `-` |

本工单优先覆盖日期时间字段；如页面明确只展示日期，再使用仅日期格式。

### 4. 实现方式

#### 4.1 公共工具

建议新增：

- `backoffice-web/src/utils/datetime.ts`

建议方法：

```ts
export function formatDateTime(value?: string | number | Date | null): string
export function formatDate(value?: string | number | Date | null): string
```

要求：

1. 支持 ISO8601 字符串。
2. 支持 `Date`。
3. 支持时间戳时保守处理，避免秒/毫秒误判导致错误。
4. 空值返回 `-`。
5. 非法时间返回 `-`。
6. 使用 `dayjs` 或项目已引入的日期库；如果没有统一日期库，可新增 `dayjs`，但必须只在公共工具内封装。

#### 4.2 表格渲染

所有时间列不再直接写：

```vue
<a-table-column title="创建时间" data-index="created_at" />
```

应改为：

```vue
<a-table-column title="创建时间" key="created_at">
  <template #default="{ record }">
    {{ formatDateTime(record.created_at) }}
  </template>
</a-table-column>
```

#### 4.3 详情区域渲染

详情弹窗、`a-descriptions` 中不再直接展示原始字段：

```vue
{{ detailModal.data.created_at || '-' }}
```

应改为：

```vue
{{ formatDateTime(detailModal.data.created_at) }}
```

#### 4.4 当前时间刷新文本

页面内主动生成当前时间的地方，例如：

```ts
lastUpdatedText.value = new Date().toLocaleString();
```

应统一改为：

```ts
lastUpdatedText.value = formatDateTime(new Date());
```

### 6.1 用户管理列表补充字段

用户管理列表需要新增“最近使用时间”字段，用于快速判断用户最近一次活跃或使用 App 的时间。

页面：

- `backoffice-web/src/views/UsersView.vue`

建议列表字段调整为：

| ID | 用户名 | 邮箱 | 状态 | 最近使用时间 | 操作 |
| --- | --- | --- | --- | --- | --- |

字段来源建议：

1. 优先使用服务端明确提供的 `last_used_at` / `last_active_at` 字段。
2. 如果服务端当前没有该字段，需要后端在用户列表接口中补充。
3. 字段计算建议优先取用户最近一次有效行为时间，例如：
   - 最近一次 `TrustedDevice.last_seen`
   - 最近一次 `AccountDeviceSession.last_refreshed_at`
   - 用户 `last_login`
4. 具体优先级由服务端统一计算，前端不要在列表页自行拼多个字段推断。

展示要求：

1. 使用 `formatDateTime(record.last_used_at)` 或最终确定的字段名。
2. 空值展示 `-`。
3. 不允许直接展示 ISO8601 原始值。
4. 该字段也纳入 `BACKOFFICE-000002` 的全局时间格式验收。

### 7. 注意事项

1. 不修改服务端返回格式，服务端继续返回 ISO8601。
2. 不在每个页面重复实现格式化函数。
3. 不使用浏览器默认 `toLocaleString()` 直接展示。
4. 秒级精度即可，毫秒和微秒不展示。
5. 时区按前端运行环境本地时区展示；后台主要面向中国使用时，显示结果即中国常用时间。
6. 如后续后台支持多时区，应在公共工具内统一扩展，不在业务页面分散处理。

### 8. 验收标准

1. `2026-05-07T03:59:31.951067Z` 不再原样展示。
2. 后台所有日期时间统一展示为 `YYYY-MM-DD HH:mm:ss`。
3. 空时间统一展示 `-`。
4. `AITrialsView.vue`、`UsersView.vue`、`DevicesView.vue`、`AuditView.vue`、`VersionLogsView.vue` 等主要页面不再直接展示 ISO8601。
5. `lastUpdatedText` 等前端生成时间也使用同一格式。
6. 全文搜索主要时间字段，不应再出现直接 `data-index` 原样展示时间字段的表格列。
7. 前端类型检查和构建通过。
