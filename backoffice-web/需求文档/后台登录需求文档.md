## BACKOFFICE-LOGIN-000001 管理后台登录增加 30 天免密登录

### 1. 背景

当前 `SparkService 管理后台登录` 页面只支持用户名、密码登录。服务端后台登录 Token 有效期固定为 1 天：

- 前端登录页：`backoffice-web/src/views/LoginView.vue`
- 前端登录 Store：`backoffice-web/src/stores/auth.ts`
- 前端登录接口：`backoffice-web/src/api/modules/auth.ts`
- 服务端后台登录：`backoffice/views.py` 的 `AdminAuthLoginView`
- 当前后台 Token 有效期：`backoffice/views.py` 的 `ADMIN_LOGIN_TOKEN_LIFETIME = timedelta(days=1)`

管理后台属于内部运营工具，部分固定办公设备需要减少频繁登录，因此需要在登录页增加“30 天免密登录”勾选项。勾选后，本次后台登录签发的后台专用 Token 有效期为 30 天。

验收可使用已有后台账号用户名 `zhaodk`。密码不得写入需求文档、代码、日志或测试快照。

### 2. 目标

| 编号 | 目标 |
| --- | --- |
| M1 | 登录页增加“30 天免密登录”勾选框 |
| M2 | 默认不勾选，保持当前 1 天有效期行为 |
| M3 | 勾选后登录请求带上免密标识 |
| M4 | 服务端仅对后台登录接口签发 30 天后台 Token |
| M5 | 不影响 App 用户登录、App refresh token、普通 API 鉴权 |
| M6 | 退出登录仍需立即清理本地 access/refresh token |

### 3. 前端需求

#### 3.1 登录页 UI

在密码输入框下方、登录按钮上方增加勾选框：

- 文案：`30 天免密登录`
- 默认值：未勾选
- 勾选状态只影响本次登录请求，不需要单独持久化勾选值
- 表单布局保持当前 Ant Design Vue `a-form` 风格

建议形态：

```text
用户名
密码
[ ] 30 天免密登录
[ 登录 ]
```

#### 3.2 前端请求协议

`adminLogin` 增加可选参数：

```ts
adminLogin(username: string, password: string, rememberMe: boolean)
```

请求体增加字段：

```json
{
  "username": "zhaodk",
  "password": "***",
  "remember_me": true
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `username` | string | 是 | 后台登录用户名 |
| `password` | string | 是 | 后台登录密码，不允许日志明文输出 |
| `remember_me` | boolean | 否 | 是否启用 30 天免密登录；缺省按 `false` 处理 |

#### 3.3 本地存储

保持现有存储方式：

- `admin_access_token`
- `admin_refresh_token`

不新增密码存储，不新增用户名密码缓存。

勾选 30 天免密后，本地仍只保存服务端返回的 token；有效期由服务端 token 自身决定。

### 4. 服务端需求

#### 4.1 登录入参

`AdminLoginSerializer` 增加：

```python
remember_me = BooleanField(required=False, default=False)
```

#### 4.2 Token 有效期

后台登录接口根据 `remember_me` 决定后台专用 token lifetime：

| 场景 | access token | refresh token |
| --- | --- | --- |
| 未勾选 `remember_me` | 1 天 | 1 天 |
| 勾选 `remember_me` | 30 天 | 30 天 |

说明：

- 该逻辑只作用于 `/api/admin/v1/auth/login/`
- 不修改 App 登录 token 有效期
- 不修改普通用户登录、Apple 登录、手机号登录逻辑
- 不影响后台 `AdminOnlyPermission` 的权限校验

#### 4.3 推荐实现方式

不要把全局 `ADMIN_LOGIN_TOKEN_LIFETIME` 直接改成 30 天。推荐拆成两个后台专用有效期：

```python
ADMIN_LOGIN_TOKEN_LIFETIME_DEFAULT = timedelta(days=1)
ADMIN_LOGIN_TOKEN_LIFETIME_REMEMBER = timedelta(days=30)
```

签发 token 时按本次请求动态选择 lifetime，避免影响未勾选用户。

如果继续沿用 `AdminRefreshToken` / `AdminAccessToken` 子类，需要保证 lifetime 是本次请求级别，不要通过修改类变量造成并发请求互相污染。可考虑提供后台 token factory 方法，创建 token 后显式设置 `exp`。

#### 4.4 刷新 Token

当前前端 refresh 逻辑使用本地 `admin_refresh_token` 刷新 access token。30 天免密登录需要保证：

- 30 天 refresh token 在有效期内可以正常刷新
- refresh 失败后仍按现有逻辑清理本地 token 并跳转登录页
- 未勾选登录的 1 天 token 行为不变

如后续发现后台 refresh 与 App refresh 混用存在权限边界问题，可另建后台专用 refresh 接口；本工单第一期优先复用现有刷新链路。

### 5. 安全与日志要求

| 编号 | 要求 |
| --- | --- |
| S1 | 密码不得写入日志、需求文档、测试快照 |
| S2 | access/refresh token 不得明文写入业务日志 |
| S3 | 审计日志可记录 `remember_me=true/false`，用于排查登录有效期问题 |
| S4 | 非 staff / superuser 用户仍禁止登录后台 |
| S5 | 退出登录必须清理本地 token，即使 token 仍未过期 |
| S6 | 30 天免密只代表 token 有效期延长，不代表跳过权限校验 |

| 项目 | 文件 | 改动内容 |

### 7. 验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A1 | 不勾选 30 天免密登录 | 登录成功，后台 access/refresh token 有效期仍为 1 天 |
| A2 | 勾选 30 天免密登录 | 登录成功，后台 access/refresh token 有效期为 30 天 |
| A3 | 勾选后退出登录 | 本地 token 被清理，再访问后台页面跳转登录页 |
| A4 | 非管理员账号登录 | 登录失败，不能因为 `remember_me=true` 绕过后台权限 |
| A5 | 密码错误 | 登录失败，页面展示错误提示，不记录密码明文 |
| A6 | 30 天 refresh token 未过期时刷新 | 可以刷新 access token，并继续访问后台接口 |
| A7 | 30 天 refresh token 过期或无效 | 清理本地 token，跳转登录页 |

### 8. 注意事项

1. “30 天免密登录”不是保存密码，不允许在前端保存密码。
2. 不要把后台登录 token 有效期改成全局 30 天，否则未勾选用户也会被影响。
3. 不要影响 App 端用户登录 token 策略。
4. 如果后续要支持“记住我设备管理”或“后台登录设备踢下线”，应单独建工单，不和本工单混在一起。
