## 4. 用户列表查询条件

### 4.1 新增查询项

用户管理筛选区新增：

| 查询项 | 参数 | 控件 | 说明 |
|---|---|---|---|
| bundle_id | `bundle_id` | 输入框 | 按用户曾使用过的应用 bundle 查询 |
| 注册日期 | `date_joined_after/date_joined_before` | 日期范围选择器 | 查询注册时间在范围内的用户 |
| 最近使用日期 | `last_used_after/last_used_before` | 日期范围选择器 | 查询最近使用时间在范围内的用户 |

建议筛选区顺序：

```text
关键词 / 状态 / bundle_id / 注册日期范围 / 最近使用日期范围 / 查询 / 重置
```

当前关键词搜索继续保留：

```text
显示名称 / 账号标识 / 邮箱
```

### 4.2 bundle_id 查询定义

`bundle_id` 在本工单中指客户端真实应用维度，优先来自：

1. `TrustedDevice.bundle_id`
2. `AccountDeviceSession.bundle_id`
3. 必要时可兼容 `LoginAudit.bundle_id`

注意：`SocialIdentity.bundle_id` 存储的是账号身份域 `identity_scope`，不一定等同于真实客户端 bundle_id。认证信息模块可以展示它，但用户管理列表的 `bundle_id` 查询不应优先使用该字段，避免把身份域和真实应用包维度混淆。

查询语义建议：

| 场景 | 后端过滤 |
|---|---|
| 用户有任一 TrustedDevice.bundle_id 命中 | 返回该用户 |
| 用户有任一 AccountDeviceSession.bundle_id 命中 | 返回该用户 |
| 用户无设备但 LoginAudit.bundle_id 命中 | 可返回，作为兼容补充 |

匹配方式：

1. 默认支持精确匹配。
2. 前端输入不为空时 trim。
3. 如需要模糊匹配，可使用 `icontains`，但应限制最大长度并避免无索引大表慢查询。
4. 推荐第一期使用精确匹配或前缀匹配，后续根据实际排障需要扩展。

### 4.3 注册日期范围

参数：

```text
date_joined_after=2026-06-01 00:00:00
date_joined_before=2026-06-30 23:59:59
```

后端过滤：

```python
User.date_joined >= date_joined_after
User.date_joined <= date_joined_before
```

规则：

1. 只传开始时间时，查询该时间之后注册的用户。
2. 只传结束时间时，查询该时间之前注册的用户。
3. 日期解析失败返回 400，不静默忽略。
4. 前端使用统一时间格式，和后台其他页面一致。

### 4.4 最近使用日期范围

参数：

```text
last_used_after=2026-07-01 00:00:00
last_used_before=2026-07-16 23:59:59
```

`last_used_at` 当前由以下候选值计算：

1. `TrustedDevice.last_seen`
2. `AccountDeviceSession.last_refreshed_at`
3. `User.last_login`

过滤必须和列表展示、排序使用同一套 `last_used_at` 计算结果。不能出现列表显示最近使用时间为 `2026-07-16`，但筛选时因为只看 `last_login` 而查不出来的情况。

建议服务端注解：

```python
last_used_sort = Greatest(
    Coalesce(Max("trusted_devices__last_seen"), MIN_DT),
    Coalesce(Max("device_sessions__last_refreshed_at"), MIN_DT),
    Coalesce("last_login", MIN_DT),
)
```

过滤：

```python
queryset = queryset.filter(last_used_sort__gte=last_used_after)
queryset = queryset.filter(last_used_sort__lte=last_used_before)
```

空值规则：

1. 没有任何使用时间的用户，不命中最近使用日期范围。
2. 如果只按注册日期筛选，不应被最近使用时间空值影响。

## 6. 用户详情弹窗 Pro 信息收敛

### 6.1 当前问题

用户详情弹窗中 Pro 相关字段平铺过多：

```text
是否 Pro
Pro 状态
Pro 来源
Pro 开始时间
Pro 到期时间
Pro 剩余时间
```

这些字段占用基础信息区过多空间，影响管理员快速查看用户身份、认证方式和设备信息。

### 6.2 收敛方案

基础信息区只保留一个“Pro 权益”字段：

| 字段 | 展示 |
|---|---|
| Pro 权益 | `Pro · 生效中 · 到期 2026-07-31 00:58:55` |

非 Pro 示例：

```text
非 Pro
```

过期示例：

```text
非 Pro · 已过期
```

pending 示例：

```text
非 Pro · 审核中
```

详细信息不再平铺展示。如果后续仍需要查看来源、开始时间、剩余时间，可以放在 Pro 标签的 tooltip 或一个小型 popover 中，但默认页面不展开。

建议保留操作按钮：

1. 非 Pro 用户展示“发放 Pro”。
2. Pro 用户展示“回收 Pro”。
3. 按钮保留在弹窗顶部右侧，不占用基础信息描述区。

### 6.3 前端方法建议

新增格式化方法：

```ts
function proSummaryText(pro: AdminUserProSummary) {
  if (pro.is_pro) {
    return `Pro · ${proStatusLabel(pro.status)} · 到期 ${formatDateTime(pro.expires_at)}`;
  }
  if (pro.status && pro.status !== 'none') {
    return `非 Pro · ${proStatusLabel(pro.status)}`;
  }
  return '非 Pro';
}
```

基础信息区替换为：

```vue
<a-descriptions-item label="Pro 权益">
  <a-tag :color="detailModal.data.pro.is_pro ? 'green' : 'default'">
    {{ proSummaryText(detailModal.data.pro) }}
  </a-tag>
</a-descriptions-item>
```

## 7. 用户详情新增“认证信息”模块

### 7.1 业务目标

管理员查看用户详情时，需要快速判断：

1. 该用户当前账号标识是什么。
2. 该用户绑定了哪些认证方式。
3. Apple / 邮箱 / 手机 / 设备身份分别对应哪个 provider uid。
4. 不同认证身份属于哪个身份域 bundle scope。
5. 认证绑定创建和更新时间。

这对排查 Apple 私密邮箱、邮箱登录、手机号登录、设备游客升级、身份绑定冲突等问题很关键。

### 7.2 展示结构

用户详情弹窗中，在基础信息之后、登录设备信息之前新增模块：

```text
认证信息
```

模块分两部分：

1. 账号本体。
2. 绑定认证方式列表。

### 7.3 账号本体

展示：

| 字段 | 数据来源 |
|---|---|
| 用户 ID | `User.id` |
| 用户名 / 账号标识 | `User.username` |
| 显示名称 | `User.first_name` 或 serializer display_name |
| 邮箱 | `User.email` |
| 状态 | `User.is_active` |
| 注册时间 | `User.date_joined` |
| 最近登录 | `User.last_login` |

如果这些字段已在基础信息展示，认证模块中的账号本体可以更紧凑：

```text
账号标识：apple_000082
邮箱：97621528@qq.com
状态：启用
```

### 7.4 绑定认证方式列表

数据来源：

```text
accounts.models.SocialIdentity
related_name = social_identities
```

建议返回字段：

| 字段 | 说明 |
|---|---|
| `id` | 绑定记录 ID |
| `provider` | `apple/google/phone/email/device` |
| `provider_label` | 中文展示 |
| `provider_uid_masked` | 脱敏后的身份标识 |
| `provider_uid` | 默认不返回，除非有高权限 |
| `bundle_id` | 身份域 scope，不一定是真实客户端 bundle |
| `created_at` | 绑定时间 |
| `updated_at` | 更新时间 |

列表展示建议：

| 认证方式 | 身份标识 | 身份域 | 绑定时间 | 更新时间 |
|---|---|---|---|---|
| Apple | `apple_000082...` | `cn.Zhaodk.Health` | 2026-03-30 05:13:20 | 2026-06-03 18:42:46 |
| Email | `976***@qq.com` | `cn.Zhaodk.Health` | 2026-06-03 18:42:46 | 2026-06-03 18:42:46 |

脱敏规则：

1. 邮箱：复用邮箱脱敏规则。
2. 手机：复用手机号脱敏规则。
3. Apple / Google / Device：展示前 10 位和后 4 位，中间省略。
4. 空值显示 `-`。

### 7.5 无认证信息

如果用户没有 `SocialIdentity`：

1. 模块仍展示。
2. 表格空状态显示 `暂无绑定认证信息`。
3. 不影响用户详情弹窗其他模块。

### 8.2 后端查询实现

`bundle_id` 建议使用 `Exists` 子查询，避免 join 放大用户行：

```python
device_exists = TrustedDevice.objects.filter(user_id=OuterRef("pk"), bundle_id=bundle_id)
session_exists = AccountDeviceSession.objects.filter(user_id=OuterRef("pk"), bundle_id=bundle_id)
queryset = queryset.annotate(
    _bundle_device_exists=Exists(device_exists),
    _bundle_session_exists=Exists(session_exists),
).filter(Q(_bundle_device_exists=True) | Q(_bundle_session_exists=True))
```

注册日期：

```python
if date_joined_after:
    queryset = queryset.filter(date_joined__gte=date_joined_after)
if date_joined_before:
    queryset = queryset.filter(date_joined__lte=date_joined_before)
```

最近使用日期：

```python
if last_used_after:
    queryset = queryset.filter(last_used_sort__gte=last_used_after)
if last_used_before:
    queryset = queryset.filter(last_used_sort__lte=last_used_before)
```

注意：`last_used_sort` 必须在过滤前完成 annotate。

### 8.3 日期解析

建议新增或复用后台查询参数解析 helper：

```python
def parse_admin_datetime_param(request, name: str):
    ...

支持：

1. `YYYY-MM-DD HH:mm:ss`

</a-table>
```

## 10. 业务流程

### 10.1 管理员按 bundle_id 查用户

1. 管理员输入 `cn.Zhaodk.Health`。
2. 前端请求 `/api/admin/v1/users/?bundle_id=cn.Zhaodk.Health`。
3. 后端查询曾使用该 bundle 的用户。
4. 列表返回命中用户。
5. 管理员可继续点击“详细”“医疗详情”排查。

### 10.2 管理员按注册日期查用户

1. 管理员选择注册日期范围。
2. 前端传 `date_joined_after/date_joined_before`。
3. 后端按 `User.date_joined` 过滤。
4. 列表排序、分页基于过滤后的结果。

### 10.3 管理员按最近使用日期查用户

1. 管理员选择最近使用日期范围。
2. 前端传 `last_used_after/last_used_before`。
3. 后端按统一计算的 `last_used_at` 过滤。
4. 无最近使用记录的用户不命中该筛选。

### 10.4 管理员打开医疗详情

1. 管理员点击用户管理列表“医疗详情”。
2. 前端打开 `MedicalDataUserOverviewModal`。
3. 弹窗调用现有医疗数据用户成员接口。
4. 有医疗数据时展示用户摘要和成员列表。
5. 无医疗数据时展示空状态。
6. 管理员可点击“打开医疗数据页”进入完整页面。

### 10.5 管理员查看认证信息

1. 管理员点击“详细”打开用户详情。
2. 后端返回用户基础信息、认证身份、设备、会话等数据。
3. 前端在“认证信息”模块展示绑定认证方式。
4. 管理员可根据 Apple、Email、Phone、Device 等身份判断账号来源和绑定状态。
