# 医院知识库产品需求与落地方案（确认版）

> 状态：需求已确认，待实施  
> 日期：2026-09-01  
> 范围：医院后台“知识库”、智能体绑定、服务端检索、iOS 患者端会话内同步  
> 非范围：不实现代码；不改动既有 `KnowledgeBase`、`KnowledgeDocument`、`AIScenarioModelBinding` 的通用逻辑

## 1. 产品目标与边界

为医院建立可复用的院内知识资产：医院职工在医院后台录入文本资料，按科室分类；医院管理员或职工在创建、维护医生智能体时手工选择关联；患者进入对应智能体的对话后，客户端后台同步该智能体关联知识库的正文、切块和已生成向量，用于本地检索与预览。

本期是演示版本，重点是“文本资料 → 智能体关联 → AI 检索 → 患者会话内同步”的完整闭环。没有审核流、文件上传、原始病历入库、自动向量化和患者端独立知识库入口。

## 2. 已确认的产品规则

| 主题 | 确认规则 |
| --- | --- |
| 业务所有权 | 知识库归 `Hospital` 所有；录入人只是 `created_by`。底层通用 `KnowledgeBase.user` 固定由该医院专属受控 service User 承载。 |
| 内容结构 | 保持现有设计：一个 `KnowledgeBase` 是资料容器，多个 `KnowledgeDocument` 是具体文本。不得复制出第二套知识库、文档、记忆或智能体配置模型。 |
| 创建方式 | 仅支持文字录入；不支持 PDF、Word、Markdown、TXT、图片、扫描件、OCR、网页抓取、附件或批量导入。按钮与页面文案使用“新建文本资料”，不使用“上传文件”。 |
| 使用者 | 能进入医院后台知识库页面的医院职工、管理员等均可新建、编辑、预览、生成向量、删除；本期不再区分这些动作的额外权限。 |
| 审核 | 演示版本不设置上传审核、医学审核、发布审批或待发布状态。保存即生效，创建后即可被智能体关联。 |
| 科室 | 知识库支持多选科室，作为资料分类和智能体关联时的搜索筛选条件；不是授权边界。 |
| 关联范围 | 所有医院知识库均为医院级资料，医院内任一智能体都可被手工关联。绝不自动绑定到全部智能体。 |
| 智能体绑定 | 新建智能体时可多选关联；已创建智能体在维护表单中可新增、解除和排序关联。复用 `ClinicalAgentKnowledgeBinding`，一库可关联多个智能体、一智能体可关联多个知识库。 |
| 保存生效 | 文本保存后立即生效；已关联智能体的下一次 AI 请求使用最新正文。患者下次进入该智能体对话时拉取最新内容。 |
| 删除 | 允许删除，服务端采用软删除。删除后停止智能体检索；患者下次该智能体范围同步时收到删除标记并清理本地正文、切块、向量。 |
| 向量 | 保存文本后不自动切块或生成向量。用户在预览页手工选择 Embedding 模型并点击“生成向量”。 |
| 模型选项 | 只显示已启用、已绑定 `embedding` 场景且其模型仍启用的 `AIScenarioModelBinding`。不修改 `AIScenarioModelBinding` 的既有选择逻辑，也不把普通聊天模型误列入。 |
| 向量失效 | 正文变更后原向量立刻标为“已过期”，不能参与当前正文检索。未生成或过期时，服务端与客户端均退回关键词/全文检索，并明确显示“向量待生成/已过期”。 |
| 患者同步 | 进入对话页不等待同步；先正常打开会话，再异步完整同步该智能体关联资料的正文、切块、已生成向量和删除标记。仅同步当前智能体关联的知识库。 |
| 患者权限 | 患者端只读，不允许新建、编辑、删除、上传或 Push 医院知识。服务端和 iOS 均须限制。 |
| 患者端呈现 | 医院知识不出现在个人“知识库”Tab，不参与普通 AI 对话。本期不新增对话页独立“知识库”入口；自动同步只服务于当前医院智能体对话。已有预览/下载能力如后续露出，也只能在该智能体会话作用域内承载。 |
| 解除关联 | 解除后立即更新智能体知识库 manifest。患者下次进入或同步该智能体时，收到解除标记并删除该智能体范围内的对应缓存。 |

## 3. 后台产品需求

### 3.1 入口与列表

医院详情导航调整为：

```text
概览｜基础资料｜科室｜职工与医生｜智能体｜知识库｜服务接入｜审计记录
```

“知识库”页展示医院级资料容器。列表字段：名称、关联科室、文本资料数量、关联智能体数量、向量状态、最后更新人、最后更新时间、操作。支持按名称、科室、向量状态搜索筛选；右上角主按钮为“新建知识库”。

```text
知识库
[搜索名称] [全部科室⌄] [全部向量状态⌄]                         [新建知识库]

名称                  关联科室       文本资料  智能体  向量状态       更新时间        操作
糖尿病患者教育资料库   内分泌科/全科   3        2       已生成（当前）  09-01 15:30    [预览] [编辑] [删除]
呼吸道症状分诊资料库   呼吸内科       2        1       已过期          09-01 14:10    [预览] [编辑] [删除]
```

删除须二次确认，明确说明：不删除患者历史对话；停止新检索；下次同步会移除该智能体范围的本地缓存。

### 3.2 新建与维护知识库

新建页只建立容器并维护分类；文本在详情页逐篇录入，避免一个“知识库”与一篇长文混淆。

```text
新建知识库
名称 *                [________________________________]
关联科室 *            [多选科室                             ⌄]
简介                  [________________________________]

                                      [取消] [保存并进入资料维护]
```

规则：名称必填且医院内不重复；关联科室至少一个、可多选；简介可空；保存后立即可在智能体表单中被选择。

详情页包含“基本信息｜文本资料｜关联智能体｜向量”四个区块：

```text
糖尿病患者教育资料库                                      [编辑基本信息]
内分泌科 / 全科                    3 篇资料 · 2 个智能体 · 向量已过期

文本资料                                                    [新建文本资料]
标题                    字数       当前版本       最后修改             操作
低血糖自我处理建议       1,280      r4             王医生 09-01 15:30  [预览] [编辑] [删除]

向量
当前状态：已过期（资料正文在 r4 后变更）
Embedding 模型 *       [从已启用 Embedding 场景模型中选择                 ⌄]
说明：不会自动生成；点击后按当前全部文本生成切块和向量。
                                                     [生成向量]
```

“新建/编辑文本资料”字段只有标题、正文。保存立即更新文档 revision、知识库 revision 和关联智能体 manifest；若正文发生变化，已有向量状态变为 `stale`。

### 3.3 智能体创建与维护中的关联

沿用智能体工单的同一维护 Drawer，增加“关联知识库”多选区：

```text
关联知识库
[按名称或科室搜索知识库________________________]
□ 糖尿病患者教育资料库      内分泌科 / 全科      已生成（当前）
□ 呼吸道症状分诊资料库      呼吸内科             向量待生成

已选（可拖动排序）
1. 糖尿病患者教育资料库                                  [解除关联]
```

列表只查询当前医院未删除的知识库；科室用于帮助检索和理解，不限制选择。保存时原子写入智能体资料、`ClinicalAgentProfile`、`AIScenarioModelBinding`（如本次为新建智能体）及 `ClinicalAgentKnowledgeBinding`。绑定行固定使用现有 `usage_scope=hospital`，不在本期启用 department/doctor 授权语义。

## 4. 服务端落地方案

### 4.1 复用与新增边界

复用：

- `chat_sync.ai_models.KnowledgeBase`、`KnowledgeDocument` 的正文、revision、软删除和同步数据语义；
- `hospital_care.ClinicalAgentKnowledgeBinding` 的多对多智能体绑定；
- `ai_config.AIScenarioModelBinding` 的 Embedding 场景模型配置与现有模型选择逻辑；
- 当前知识同步的 cursor、revision、tombstone、single-flight 等协议语义。

新增仅放在 `hospital_care`（或其紧邻的医院知识应用）中，不能修改通用个人知识库的所有权逻辑：

| 新增实体 | 核心字段与用途 |
| --- | --- |
| `HospitalKnowledgeBaseProfile` | `hospital`、`knowledge_base`（一对一）、`created_by`、`updated_by`、`department` 多对多分类、`vector_status`、`indexed_revision`、`embedding_binding`、`deleted_at`。医院业务归属与技术服务账号映射由此表达。 |
| `HospitalKnowledgeBaseDepartment` | `profile`、`department`；仅分类/筛选，不参与访问控制。 |
| `HospitalKnowledgeChunk` | `profile`、`document`、`document_revision`、`chunk_index`、`content`、`content_hash`、`vector_payload`、`embedding_binding`。只保存手工生成且仍对应当前 revision 的切块与向量，供服务端和患者同步。 |
| `HospitalAgentKnowledgeManifest`（可计算，不必持久化） | 由智能体绑定、知识库 revision、文档 revision、向量状态组成；供会话进入和同步比对。 |

`HospitalKnowledgeChunk` 不是第二套文档模型，而是现有文本资料在某个版本、某个 Embedding 模型下的可再生成索引。正文永远以 `KnowledgeDocument` 为唯一事实源。

### 4.2 医院 service User

创建医院时或首次启用知识库时，系统幂等创建医院专属 service User；所有该医院 `KnowledgeBase`、`KnowledgeDocument` 的 `user` 统一指向它。前台操作者通过 `created_by/updated_by` 留痕，不能成为底层 owner。

任何医院知识操作都先校验当前操作者拥有该医院后台访问资格，再通过服务层解析医院 service User；禁止直接把任意 `KnowledgeBase` 的 `user` 改为当前登录用户，禁止跨医院按 ID 读取。

### 4.3 文本与向量状态机

```text
新建知识库 / 新建文本 ──保存──> 待生成
待生成 ──手工选择 Embedding 模型并生成成功──> 已生成（当前）
已生成（当前） ──正文变更──> 已过期
已过期 ──手工重新生成成功──> 已生成（当前）
任意状态 ──删除──> 已删除（对同步下发 tombstone）
```

向量生成动作必须显式提交 `embedding_binding_id`。服务端验证：绑定存在、`scenario=embedding`、绑定启用、关联模型启用、模型 Provider 配置可用；不满足时返回可读错误，不执行生成。生成任务可以异步运行，但**只能由手工按钮触发**，绝不由保存文本、定时任务或患者请求隐式触发。

正文 revision 与 `indexed_revision` 不相等时为过期。服务端检索、患者同步和本地检索都不得使用该旧向量；此时执行关键词/全文检索降级。

### 4.4 接口契约

后台管理接口建议置于医院模块，所有对象均由 `{hospital_id}` 限定：

| 动作 | 接口示例 | 结果 |
| --- | --- | --- |
| 列表/筛选 | `GET /api/v1/hospital-care/hospitals/{hospital_id}/knowledge-bases/` | 返回资料容器及科室、绑定数、向量状态摘要。 |
| 新建/编辑容器 | `POST/PATCH .../knowledge-bases/{id}/` | 创建或修改资料库分类、名称、简介；返回 revision。 |
| 文本资料 CRUD | `GET/POST .../knowledge-bases/{id}/documents/`；`PATCH/DELETE .../documents/{document_id}/` | 只接收 `title`、`content`；不接受 file、URL、OCR 字段。 |
| 预览 | `GET .../knowledge-bases/{id}/preview/` | 返回当前正文、版本、切块/向量状态，供后台查看。 |
| 手工生成向量 | `POST .../knowledge-bases/{id}/vector-build/` | 请求含 `embedding_binding_id`；返回任务/状态。 |
| 删除容器 | `DELETE .../knowledge-bases/{id}/` | 软删除、解除检索、发布同步 tombstone。 |
| 智能体关联候选 | `GET .../agents/knowledge-base-options/` | 只返回本院未删除容器及分类、向量状态。 |

患者端不复用个人账号的 `/api/v1/ai/knowledge/sync/push/` 来读取医院 service User 数据。新增仅拉取的、会话/智能体作用域同步入口，例如：

```text
GET /api/v1/hospital-care/agents/{agent_id}/knowledge-sync/manifest/
GET /api/v1/hospital-care/agents/{agent_id}/knowledge-sync/pull/?cursor=...
```

服务端从当前患者身份、就诊成员、会话所属医院和智能体绑定四项联合校验可见范围。`pull` 响应沿用现有同步 DTO 的 `cursor`、upsert、revision、deleted/tombstone 语义，但只返回当前智能体绑定的资料、当前正文、有效切块和有效向量。没有 `push`、写入、冲突解决接口。

### 4.5 AI 运行时检索

每次医院智能体 AI 请求在服务端构建当前 manifest：只取该智能体现存、未删除的绑定资料及最新文本。优先检索 `indexed_revision` 等于当前 revision 的向量切块；任一资料无有效向量时，对那部分文本使用关键词/全文检索。响应/审计应记录 `knowledge_base_id`、`document_id`、正文 revision、chunk hash、检索方式（vector 或 keyword），使历史回答可解释。

解除或删除后立即从新 manifest 排除；正在执行的请求可以完成，但后续请求不得继续选中该资料。

## 5. iOS 患者端落地方案

### 5.1 同步时机与范围

患者进入医院智能体对话：

```text
打开对话页（不阻塞）
        │
        ├─ 正常在线 AI 对话 / 服务端检索
        │
        └─ 后台拉取 agent knowledge manifest
                 │
                 └─ 按 cursor 同步正文、切块、有效向量、删除标记
                            │
                            └─ 完成后可在本地直接检索
```

复用当前 iOS 知识同步的网络协议、增量 cursor、任务合并、取消与本地 embedding/检索基础能力，但将来源扩展为只读 `agent_hospital` 作用域。它不是个人知识库同步：不复用个人 cursor，不写个人 Outbox，不出现在个人知识库 Tab，也不能参加普通 AI 对话。

本地缓存主键至少包含：`account_id + member_id + hospital_id + agent_id + knowledge_base_id + document_id + revision`。账户切换、成员切换、医院/智能体解除关联、服务端 tombstone、退出登录或缓存过期时，取消旧任务并清理该作用域的正文、切块、向量与密钥材料。

### 5.2 本地检索与降级

- 完成同步且向量有效：优先本地向量检索；
- 未同步完成、向量待生成或已过期：允许正常咨询，本地使用关键词/全文检索；
- 无网络：只能使用已同步且仍有效的医院智能体作用域资料；不得误把个人知识或另一个智能体资料带入；
- UI 在内部/必要提示处显示“向量待生成”或“向量已过期”，不能假装为语义检索结果。

本期不新增对话页“医院知识库”菜单、患者个人知识库页或全局下载页。资料下载是进入会话后的后台同步行为；后续若开放患者显式预览/下载，必须继续受当前医院与智能体作用域约束，并保持只读。

## 6. 验收标准

1. 任一医院后台可访问者新建医院资料库，底层 `KnowledgeBase.user` 为医院 service User，创建人可追溯。
2. 只能新增、编辑文字资料；所有文件、URL、OCR 与审批入口均不存在或被接口拒绝。
3. 资料可选择多个科室；科室仅用于筛选，任一本院智能体均可手工关联。
4. 新建和维护智能体均能多选、解除、排序关联知识库；绑定不复制正文。
5. 正文保存后，新 AI 请求使用新正文；旧向量立即不可用于该版本。
6. 仅手工点击后生成切块向量，模型候选只来自启用中的 Embedding 场景绑定。
7. 无有效向量时服务端和客户端都可关键词/全文检索；没有任何自动补向量动作。
8. 患者进入对话不被同步阻塞；仅同步当前智能体关联资料的正文、切块、有效向量和删除标记。
9. 医院资料不显示在个人知识库，不参与普通 AI 对话；患者无法对其 Push、编辑或删除。
10. 解除关联或删除后，下一次该智能体同步清除本地对应缓存；其他智能体关联的同一资料不被误删。

## 7. 实施顺序

1. 建立医院 service User 解析与 `HospitalKnowledgeBaseProfile`、科室分类、手工索引实体；迁移历史医院演示知识库。
2. 完成医院后台知识库列表、文本资料 CRUD、预览、手工向量生成及软删除接口。
3. 在新建/维护智能体表单中接入本院知识库候选与 `ClinicalAgentKnowledgeBinding` 原子保存。
4. 将医院智能体运行时检索接入 manifest，落实向量/关键词降级和检索审计。
5. 新增只读的 agent scoped manifest/pull 同步接口，并编写 tombstone 行为测试。
6. iOS 在既有同步框架中增加只读医院智能体作用域，完成非阻塞同步、隔离缓存和删除清理。
