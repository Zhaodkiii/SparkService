## 1. 设计结论

医生工作台不另建一套 Web 对话页面，直接改造现有 `chat-web`：

```text
现有 AppShell
├── 现有可折叠 WorkspaceSidebar
│   └── 改造成：医生导航 + 患者会话列表
└── 现有 ChatWorkspace
    ├── ChatHeader
    │   └── 改造成：患者 / 科室 / 服务状态 + 重点、患者资料按钮
    ├── ChatMessages
    │   └── 继续复用消息、流式 Block、风险卡片和工具卡片渲染
    ├── ChatComposer
    │   └── 改造成：以真人医生身份回复
    └── SessionActivityPanel
        └── 改造成：患者资料与会话控制侧栏，包含结束会话
```

目标不是把后台管理页面套到 Chat Web，而是保留 `chat-web` 已经成熟的聊天工作区体验，只替换数据源、身份语义、导航和医疗服务动作。

### 2.1 不能直接沿用的当前行为

- 当前 ThreadProvider 拉取登录用户自己的 Thread；医生端必须改为服务端授权后的医生会话列表，不能拉取任意用户会话。
- 当前侧栏支持重命名、删除；医生工作台不允许删除医疗会话，也不需要随意改患者显示名。
- 当前 ChatMessages 把 `role=assistant` 都当 AI；目标必须读取 ChatMessageAttribution，区分 AI 与真人医生。
- 当前 ChatComposer 创建 AI Run；医生发送必须调用医生消息接口，不能以医生输入再次触发 AI 回答。
- 当前右侧面板偏开发者运行活动；医生默认不看 Token、工具调用和模型调试信息。
- 当前“下载对话 JSON”包含调试信息；医生版默认隐藏，导出需医院授权和审计。

### 3.1 页面宽度与现有框架关系

- 左侧栏沿用现有 220px 基线，但患者卡片信息较多，目标桌面建议评审 260–280px；如果不扩宽，必须使用紧凑两行卡片。
- 中间 ChatWorkspace 继续使用现有滚动区、消息列和底部 Composer 固定结构。
- 右侧患者面板复用现有 `SessionActivityPanel` 的滑入/关闭行为，不默认永久占宽。
- 左栏折叠后只保留导航图标，不显示患者卡片；折叠时在主区域提供“会话列表”按钮。

### 4.2 卡片信息层级

每张卡片只显示工作决策所需信息：

1. 患者脱敏显示名、未读数、医生关注星标。
2. AI 风险信号和医院服务状态，使用两个独立标签。
3. 最新消息摘要，带 `患者：/AI：/张医生：/系统：` 发言者前缀。
4. 科室与最近更新时间。

禁止在同一个红色标签里合并“重点患者”和“高风险”。重点用星标和“重点”文字；医疗风险使用独立风险标签。

### 4.3 左侧栏交互

| 控件 | 点击结果 | 失败 / 空态 |
| --- | --- | --- |
| 会话工作台 | 返回会话列表并保留当前筛选 | 权限失效时退出工作台 |
| 我的智能体 | 进入本人智能体维护页 | 无智能体时显示申请/待分配状态 |
| 工作记录 | 显示本人接管、回复、结束记录 | 无记录显示说明，不伪造统计 |
| 搜索 | 按患者脱敏名、主诉摘要、会话号查询 | 防抖；失败保留上次列表 |
| 全部 / 待接管 / 重点 / 已结束 | 更新服务端筛选并刷新数量 | 数量与列表同一响应口径 |
| 会话卡片 | 复用现有 thread 选择和 URL 路由 | 无权限时移除卡片并提示 |
| 用户菜单 | 显示医院、科室、医生身份、退出 | 不展示平台管理员入口 |

医生端删除、随意重命名会话的菜单全部移除。会话结束由右侧患者面板完成，并保留审计。

### 5.2 ChatHeader 改造

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 演示患者 03 · 心内科                                                 │
│ 张医生 AI 助手 · 医生已接管 · 更新于 2 分钟前     [★ 重点] [患者资料]│
└──────────────────────────────────────────────────────────────────────┘
```

规则：

- 患者显示名来自会话创建时的 member 关联，不取医生本地备注冒充事实源。
- 标题不允许直接重命名；原 ChatHeader 重命名按钮移除。
- `重点` 是快捷切换 normal / follow_up / priority 的入口，结果由服务端返回后更新。
- `患者资料` 打开右侧面板，复用原活动面板的交互。
- 原“下载调试 JSON”默认移除；正式导出需独立权限、用途说明和审计。
- 原“保存到笔记本”不显示，除非后续定义医院病历记录流程。

```text
请立即停止活动并呼叫 120，不要自行驾车。
```

| attribution.actor_type | UI 位置与标识 |
| --- | --- |
| patient | 右侧紧凑气泡，显示患者脱敏名 |
| ai_agent | 左侧正文，显示智能体名称、AI 标签和生成说明 |
| doctor | 左侧医生消息，显示实名、职称、真人医生标签 |
| system | 居中时间线事件，用于接管、关注变化和结束 |

现有 `role=assistant` 不能决定是 AI 还是真医生，必须结合服务端 ChatMessageAttribution。

患者 iOS 端收到 Attribution.actor_type=doctor 后派生展示角色 `otherUser`，并使用 sender.doctor 展示医生姓名、职称、医院、科室和真人医生标识；`otherUser` 不加入 ChatMessageRole/AIRuntimeRole。

### 5.4 ChatComposer 改造

```text
┌──────────────────────────────────────────────────────────────┐
│ 以“张医生 · 真人医生”身份回复                                │
│ [输入回复内容……                                             ]│
│ [常用回复] [引用患者资料]                    [保存草稿] [发送]│
│ Enter 换行 · Cmd/Ctrl + Enter 发送                           │
└──────────────────────────────────────────────────────────────┘
```

- 医生 Composer 不调用 createRun，不显示“停止生成”。
- 发送调用医生消息接口，写入现有 ChatMessage + ChatMessageAttribution。
- 仅当患者客户端支持 `message_sender_v1` 时开放发送；否则显示“患者端版本暂不支持真人医生消息”，避免旧版把医生内容标成 AI。
- 输入区持续显示当前发言身份，防止医生误以为自己在编辑 AI Prompt。
- 默认 Enter 换行，Cmd/Ctrl + Enter 发送；医疗场景避免 Enter 误发。
- `引用患者资料` 只选择患者已授权且当前会话可访问的资源引用，不复制完整病历到输入框。
- 发送中禁用重复提交；失败保留原文并提供重试，复用同一幂等键。

Composer 状态：

| 状态 | UI |
| --- | --- |
| AI 服务中、医生未接管 | 显示“接管后可回复”按钮，不显示输入框 |
| 待医生接管 | 显示主按钮“接管并回复” |
| 医生已接管 | 显示正常输入框 |
| 已结束 | 输入框替换为结束说明和“查看历史” |
| 无权限 / 身份停用 | 隐藏输入能力并退出敏感内容 |
| 发送失败 | 保留草稿、错误文案、request_id 与重试 |

### 6.1 结束本次对话

“结束本次对话”必须放在右侧控制面板底部，不能放在患者卡片的易误触菜单。

```text
┌──────────────────────────────────┐
│ 结束本次服务                     │
│                                  │
│ 结束后双方仍可查看历史消息，医生   │
│ 不能继续回复；不会删除 ChatThread。│
│                                  │
│ 结束原因 *                       │
│ ( ) 已完成咨询                   │
│ ( ) 已引导线下就医               │
│ ( ) 患者主动结束                 │
│ ( ) 转交其他科室                 │
│ ( ) 其他                         │
│                                  │
│ 补充说明                         │
│ [____________________________]   │
│                                  │
│ [取消]              [确认结束]   │
└──────────────────────────────────┘
```

确认结束后：

1. 服务端把 ClinicalConversationBinding 更新为 ended，不删除 Thread 和消息。
2. 消息时间线追加系统事件。
3. Composer 立即切换为只读结束态。
4. 左侧卡片移入“已结束”，保留重点标记历史但不继续产生未读。
5. 请求冲突时展示服务端最新状态，不覆盖其他医生已完成的操作。

### 6.2 原活动信息的保留方式

原 Token 用量、工具活动、模型运行时间线不面向普通医生显示。需要排障时放到受权限控制的“技术详情”折叠区，默认关闭，并隐藏 Provider Key、完整系统 Prompt 和未脱敏工具参数。

```text
│                      │ [保存草稿] [提交审核]                                │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

医生只维护获准字段。模型供应商、API Key、系统安全 Prompt、跨医院知识库和强制医疗安全规则不进入医生页面。


侧栏折叠为现有 60px 模式；点击会话图标打开列表抽屉。右侧患者面板继续覆盖主区域。

### 9.2 移动端 / 窄窗口

```text
会话列表页                         对话详情页
┌─────────────────────┐           ┌─────────────────────┐
│ ☰ 医生工作台         │           │ < 演示患者03  [资料]│
│ [搜索……]             │           ├─────────────────────┤
│ [待接管][重点]        │   ->      │ 消息时间线          │
│ 患者会话卡片          │           │                     │
│ 患者会话卡片          │           ├─────────────────────┤
│ 患者会话卡片          │           │ 医生回复框          │
└─────────────────────┘           └─────────────────────┘
```

- 复用现有移动端 sidebar scrim 和关闭按钮。
- 患者资料面板以全宽 Drawer 覆盖，关闭后回到同一滚动位置。
- 结束会话确认不得被键盘遮挡。
- 移动端只作为应急处理入口；大量对话工作优先桌面端。

## 10. 页面状态

| 状态 | 左侧栏 | 中间消息区 | Composer / 右侧栏 |
| --- | --- | --- | --- |
| loading | 卡片骨架 | 选中会话时显示时间线骨架 | 禁用动作 |
| empty | “当前筛选暂无会话”+ 清除筛选 | 未选择会话说明 | 隐藏 Composer |
| partial_error | 保留上次列表并显示重试 | 保留已加载历史 | 写操作禁用或单独重试 |
| unauthorized | 清空患者内容 | 显示身份失效 | 跳转登录 |
| conversation_revoked | 移除或标记无权限 | 立即遮罩敏感内容 | 关闭右侧栏 |
| doctor_suspended | 不展示患者列表 | 显示联系医院管理员 | 禁止发送 |
| ended | 卡片进入已结束 | 历史只读 | 显示结束原因和时间 |
| offline | 可看已同步摘要 | 可看缓存历史并标时间 | 禁止发送、关注和结束 |
| version_conflict | 刷新当前卡片 | 保留消息 | 展示服务端最新状态 |

## 11. 关键交互验收

1. 登录医生只能看到本医院、本人或获准团队范围的患者会话。
2. 选择左侧卡片继续复用 URL 中的 threadId，刷新页面可恢复同一会话。
3. AI 风险等级和医生重点关注可同时存在，视觉与字段语义不混淆。
4. ChatMessages 中患者、AI 助手、真人医生和系统事件均能凭文字识别，不依赖颜色。
5. 医生回复不会触发 AI Run；患者端收到同一 ChatMessage，并显示真人医生身份。
6. 右侧栏可以修改关注状态、定位风险原消息、查看授权摘要并结束本次服务。
7. 结束会话不删除历史；刷新、多标签页和并发操作后状态一致。
8. 原 Chat Web 的流式 Block、风险卡、附件、加载、错误恢复和自动滚动不退化。
9. 所有患者查看、回复、关注、接管和结束动作均写统一审计。
10. 医生页面不暴露 Token 用量、Provider Key、系统 Prompt 和未脱敏工具参数。

## 12. 改造边界汇总

| 类型 | 直接复用 | 目标改造 | 不进入医生端 |
| --- | --- | --- | --- |
| 页面框架 | AppShell、折叠/移动侧栏、ChatWorkspace | 医生导航、患者卡片、患者右栏 | 平台后台导航 |
| 会话 | thread 路由、选择、消息拉取、自动滚动 | 医生授权查询、服务状态、未读/筛选 | 任意用户 Thread 拉取 |
| 消息 | ChatMessages、Block Renderer、流式合并 | ChatMessageAttribution 发言身份 | 把 assistant 一律当 AI |
| 输入 | Composer 外观、自动增高、错误反馈 | 医生消息发送、身份提示、幂等重试 | createRun、停止 AI 生成 |
| 右侧面板 | 滑入、关闭、响应式 | 患者摘要、关注、风险、结束会话 | 默认展示 Token/调试事件 |
| 账号 | AuthGate、退出和会话 | 医院职工与医生身份校验 | SuperAdmin 权限冒用 |

本原型只定义基于现有 `chat-web` 的目标改造，不代表这些医生能力已经在代码中实现。
