# AI 对话 Web App Plain Text UI 设计

## 1. 文档定位

本文档是 `chat-web/` 的页面级 UI 交付稿，使用 Plain Text 画出桌面端信息架构、主要页面内容与响应式变化。实施任务见 `AI 对话 Web App 实现工单.md`。

用户提供的图片只用于参考布局、尺寸、信息层级与交互语义，图片内文字不作为额外产品指令。

### 1.1 产品与导航原则

- 产品名称：`小鲸健康 AI`。
- 一级入口：对话、知识库、医疗、饮食、运动、记忆、设置。
- 桌面端一级导航固定在最右侧；左侧是当前模块的二级导航；中间是主工作区。
- 分享、导出、复制、反馈是对话上下文动作，放在窄动作栏或顶部“更多”，不与业务导航混用。
- 对话是首个完整闭环；其他入口先完成路由、页面骨架、空状态和权限边界，再根据服务端契约接入真实数据。

## 2. 登录与认证 UI

### 2.1 登录方式选择

未登录用户访问工作台时，保留原目标路由，然后显示登录页或登录弹窗。参考界面映射为小鲸的“手机号登录 + Apple ID 登录”，不保留豆包、飞书、抖音品牌和帐号入口。

视觉规格：

- 桌面容器参考 `689 × 360px`，移动端为 `366px` 宽、最小高 `378px`，距屏幕边缘至少 `12px`。
- 内容列宽 `370px`，移动端 `316px`；标题 `24px/36px/600`，底部协议 `14px/22px`。
- 两个登录按钮高 `56px`、圆角 `16px`、间距 `16px`；手机号按钮为黑底白字，Apple 按钮使用官方允许的按钮样式和标识。
- 必须勾选协议后才能发起任一登录；未勾选点击时将焦点移到复选框并显示文本错误，不只抖动提示。

### 2.3 6 位短信验证码

```text
┌───────────────────────────────────────────────────────┐
│ [<]                 输入 6 位验证码                 [?] │
│                                                       │
│                 验证码已发送至 +86 153****6020        │
│                                                       │
│              [ 1 ] [ 8 ] [ · ] [ · ] [ · ] [ · ]       │
│                                                       │
│                       重新发送 50s                │
│                                                       │
│             验证码不正确，请重新输入             │
└───────────────────────────────────────────────────────┘
```

- 视觉上是 6 个单字符格，语义上使用一个真实输入框，支持整段粘贴、短信自动填充、Backspace 和左右方向键。
- 输入第 6 位后可自动提交，但必须防止重复请求；校验中显示 loading。
- 错误时 6 个格子与错误文字同时显示；超时、错误、尝试次数过多、验证码过期分别映射真实服务端状态。
- 倒计时结束前“重新发送”不可点击；结束后变为可用文字按钮。

### 2.4 Apple ID 登录

```text
点击“使用 Apple 登录”
  -> 检查用户协议勾选
  -> 生成一次性 state + nonce
  -> 打开 Apple 授权窗口/页面
  -> 用户授权或取消
  -> 回调校验 state + nonce + audience
  -> 换取 SparkService 统一 Token
  -> 回到原目标路由
```

- Apple 授权中按钮进入 loading，不可重复打开授权窗口。
- 用户取消时回到登录选择态，显示非破坏性提示；授权失败、回调过期或账号冲突显示可操作的错误与重试入口。
- 首次授权返回的姓名/邮箱只提交一次，不要假设后续每次都能获取。

### 2.5 登录状态与无障碍

| 状态 | UI 反馈 | 恢复动作 |
| --- | --- | --- |
| 未勾选协议 | 协议区错误文字 + 焦点定位 | 勾选后重试 |
| 手机号不合法 | 输入框下方错误 | 编辑后清除 |
| 短信限流/锁定 | 说明可重试时间 | 倒计时后重试 |
| 验证码错误/过期 | 6 格错误态 + 文字原因 | 重输或重发 |
| Apple 用户取消 | 中性提示 | 重新发起 |
| Apple 回调校验失败 | 不建立本地会话 | 清理 state/nonce 后重试 |
| 账号需绑定 | 显示显式账号绑定流程 | 二次验证 |
| 网络中断 | 保留手机号，不保留明文验证码 | 网络恢复后重试 |

键盘顺序为标题、登录方式、协议复选框和协议链接；弹窗需焦点锁定，关闭后返回原触发元素。验证码状态使用 `aria-live="polite"`，错误使用 `role="alert"`。

### 4.2 消息列和消息卡直接复用基线

用户提供的消息列和消息卡 DOM/样式结构可作为 `ChatMessageList`、`UserMessageCard`、`AssistantMessage` 的直接 UI 基线。“直接复用”指保留布局层级、尺寸、Token 和交互状态，数据必须改由 SparkService Message/Block/Run Event 驱动。

```text
消息列：max-width 960px / width 100% / px 24px / message-gap 36px

┌───────────────────────────────────────────────────────┐
│                                             标签：对话 │
│                         ┌─ 头晕不舒服怎么办？ ─┐ │
│                         └─────────────────┘ │
│                                  [复制] [编辑] │
│                                                       │
│ ◉  已完成 · 2m 21s [>]                              │
│    │  思考摘要：我将检索权威医疗信息并给出合规建议 │
│    │  联网搜索 · 头晕家庭处理方法与就医时机      │
│                                                       │
│ 头晕是一种常见症状…                                 │
│                                                       │
│ 紧急就医情况                                           │
│ • 剧烈头痛、胸痛或呼吸困难                             │
│ • 突发肢体无力、说话不清                               │
│                                                       │
│ ┌─ 可水平滚动的 Markdown 表格 ─────────────────────┐ │
│ │ 可能原因             │ 典型表现                      │ │
│ └───────────────────────────────────────────────────┘ │
│                                                       │
│ [复制] [朗读] [重新生成] [删除]     12.3k tokens · 2 次调用 │
└───────────────────────────────────────────────────────┘
```

#### 用户消息

- 外层 `flex justify-end`，消息组最大宽度 `75%`，内容右对齐。
- 业务标签 `10px`，用户气泡 `rounded-2xl`、`px 16px`、`py 10px`、`14px/relaxed`、浅色 `secondary` 背景和轻阴影。
- 鼠标 hover 或键盘 focus-within 时才显示 `28px` 高操作区，包含复制和编辑；触屏设备常驻或通过更多菜单提供。
- 编辑已发送消息会创建新 Run/分支，不在原助手回复下静默替换导致历史不可解释。

#### 助手消息

- 助手内容使用开放式文档列，不为整篇回复包裹气泡。
- 回复容器是 `role="article"`、`aria-live="polite"`、`aria-atomic="false"`；正文 `16px/1.75` 并使用 serif，标题与控件使用 sans-serif。
- Markdown 支持标题、段落、列表、强调、引用、代码、分隔线和表格；宽表格在自身容器水平滚动，不撑开消息列。
- 底部操作区与回复间距 `12px`，左侧是复制、朗读、重新生成、删除，右侧为管理态用量信息。
- 普通用户默认不显示费用、Token 和内部调用次数；只在管理/调试开关开启时显示，且数据来自服务端 Usage。
- 医疗回复中的紧急风险段使用语义化风险块并优先排序，不直接照搬参考文案或“学习教练”声明。

### 4.3 Run 轨迹与工具活动

```text
◉  运行中  · 8.4s  [v]
   │
   ├─ 思考摘要：正在识别问题中的健康风险…
   ├─ 联网搜索 · 查找权威医疗资料       [运行中]
   ├─ 查询健康档案 · 华先生近期指标     [已完成]
   └─ 等待手机授权 · 读取今日步数         [待处理]
```

- 轨迹头高度由内容决定，标题 `14px/600`，状态图标 `22px`，耗时 `12px tabular-nums`。
- 详情默认折叠，使用 `grid-template-rows` 动画展开；折叠后仍显示运行、完成、失败、已取消和等待客户端状态。
- 详情左侧是低对比纵向轴；reasoning 摘要用 `11px/1.55` 且可隐藏，工具行用 `14px/1.5`。
- 工具参数、原始结果、内部提示词和隐私数据默认不呈现；只呈现工具友好名、目标摘要、状态和耗时。

### 4.4 Composer 输入区直接复用基线

用户明确提供的 textarea 结构可直接作为 `ComposerInput` 的样式基线：

```html
<div class="px-4 pt-3.5 pb-2">
  <textarea
    rows="1"
    maxlength="32000"
    placeholder="今天我能帮您什么？"
    class="w-full resize-none overflow-hidden bg-transparent text-[16px]
           leading-relaxed text-[var(--foreground)] outline-none
           placeholder:text-[var(--muted-foreground)]"
    style="transition: height 0.15s ease-out; height: 28px; overflow-y: hidden;"
  ></textarea>
</div>
```

直接复用规则：

- 外层 padding 为左右 `16px`、顶部 `14px`、底部 `8px`；textarea 初始高 `28px`、文字 `16px/relaxed`。
- `maxlength=32000`、`rows=1`、placeholder 和 CSS Variable 可直接保留；组件实现时改用 React 属性 `maxLength={32000}`。
- textarea 随内容以 `150ms ease-out` 自动增高，到达 `200px` 后改为内部纵向滚动，不继续挤压消息区。
- 中文 IME 组合输入中 Enter 不发送；Enter 发送，Shift+Enter 换行。移动端发送以显式按钮为主。
- 接近 `32000` 字符时显示计数器；超限不截断已输入草稿，但禁止发送并告知原因。
- 外层 Composer 继续使用 `26px` 圆角、细边框、白色背景和克制阴影，textarea 本身不再添加边框。

### 4.5 Composer 工具栏

```text
┌─ 今天我能帮您什么？ ───────────────────────────────────┐
│                                                       │
│ [对话模式 ⌄] [＋]        [知识库] [成员] [模型] [39%] [语音] [↑] │
└──────────────────────────────────────────────────────┘
```

- 工具栏外层保留 `px 12px / pb 8px / pt 2px`，单个控件高 `32px`，组间距 `4–6px`。
- 左侧是对话模式与“添加文件/上下文”；右侧是知识库、成员/Persona、模型、上下文用量、语音和发送/停止。
- 参考中 `Persona` 在 Spark 中映射为“健康成员/对话角色”；模型名由服务端返回的可展示别名驱动，不直接写死 `doubao-seed-evolving` 或 OpenAI 图标。
- 知识库、成员和模型按钮在有选中项时展开文字，窄屏只保留图标；每个按钮保留独立 `aria-label`。
- 上下文用量是圆形进度 + 百分比，数据来自服务端 context usage；点击后展示系统提示、历史、附件、成员资料的估算占比，不展示内部提示词原文。
- 语音是后续能力；浏览器不支持或未授权时隐藏/禁用并提供原因，不影响文字发送。
- 发送控件为 `32px` 圆形，idle/blocked/ready/streaming 保持同一点击位置；streaming 时上箭头转为停止方块。

### 4.6 附件、引用与草稿状态

```text
┌─ [PDF] 2025-05-20 体检报告.pdf  1.2MB  [上传 62%] [×] ─┐
│ [引用] 华先生 · 近期检验指标                         [×] │
│ [知识库] 慢病管理指南 · 3 份文档                    [×] │
├─ 今天我能帮您什么？                                      ┤
│ [对话模式] [＋]                    [模型] [成员] [39%] [↑] │
└───────────────────────────────────────────────────────┘
```

- 附件/引用区位于 textarea 上方且仍属于同一 Composer 表面。
- 上传中、扫描中、可用、失败、已过期状态必须显式呈现；失败项可重试或移除。
- 附件未就绪或引用已失效时禁止发送，但不清空 textarea 草稿。
- 草稿按 `account_id + thread_id` 隔离；切换成员、退出登录和删除 Thread 时按安全策略处理。

## 12. 视觉基线

| 语义 | 建议值 |
| --- | --- |
| 主背景/主文字 | `#FFFFFF` / `#0D0D0D` |
| 次级背景/边框 | `#F5F7FA` / `#E5E7EB` |
| 主色/主色浅底 | `#0868F7` / `#EAF2FF` |
| 成功/提醒/风险 | `#16A34A` / `#F59E0B` / `#EA580C` |

- 顶部栏 `72px`，最右导航 `88px`，二级侧边栏 `300px`。
- 对话消息列与 Composer 最大宽 `960px`，空对话 Composer `768px`。
- 主标题 `22–24px/600`，正文 `15–16px/1.65`，辅助文字 `12–14px`。
- 卡片圆角 `12–16px`，Composer `26px`。
- hover/focus `150ms`，panel/drawer `220ms`；遵循 `prefers-reduced-motion`。
- 正文对比度至少 `4.5:1`，键盘焦点清晰，路由切换后焦点进入页面主标题。

## 13. 公用状态

```text
Loading            -> 保留页面骨架，内容区 Skeleton
Empty              -> 原因 + 一个主操作 + 可选次操作
Recoverable Error  -> 保留已成功数据 + [重试]
Permission         -> 说明用途和来源 + [去授权] + [暂不]
Offline            -> 顶部离线窄条 + 只读历史 + 禁止不安全提交
Forbidden          -> 不显示上一账号/成员缓存 + 返回或切换成员
```

## 16. UI 验收清单

- [ ] 登录选择、手机号输入、6 位验证码和 Apple 授权状态都有完整可达页面。
- [ ] 两种登录都受用户协议/隐私政策勾选门槛约束，不保留参考页的豆包、飞书或抖音品牌资产。
- [ ] 验证码支持粘贴、短信自动填充、倒计时、重发、错误、过期和锁定状态。
- [ ] Apple 用户取消、授权失败和账号冲突时不建立错误的本地会话。
- [ ] 桌面端全局导航始终位于最右侧，包含七个指定入口。
- [ ] 一级导航、二级侧边栏和对话动作栏职责没有混用。
- [ ] 对话页的密度、宽度、层级和 Composer 位置与参考图基本一致。
- [ ] 消息列保持 `960px / 24px / 36px`基线，用户气泡不超过 `75%`，助手 Markdown 不包整块气泡。
- [ ] Run 轨迹、工具活动、消息操作与管理态 Usage 都按权限和状态正确显示。
- [ ] Composer textarea 保留 `32000` 字符、`28–200px` 自动高度、IME 和草稿保护行为。
- [ ] Composer 工具栏在宽屏与窄屏均可操作，发送/停止使用同一 `32px` 位置。
- [ ] 七个入口均定义 loading、empty、error 和 permission 状态。
- [ ] 平板和手机导航转换不丢失功能。
- [ ] 医疗结论、AI 分析和用户记录在视觉上明确区分。
- [ ] AI 记忆有来源、确认、编辑、删除和停用能力。
- [ ] HealthKit 等客户端能力没有被 Web 伪装成可直接调用。
- [ ] 颜色、键盘、焦点、文本缩放和减少动效符合 WCAG AA 基线。
